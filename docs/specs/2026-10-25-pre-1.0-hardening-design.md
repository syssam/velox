# Pre-1.0 hardening

## Intent

The user asked, on 2026-10-25, to "make all perfect first", before the pgx split and 1.0. The followups file (docs/plans/2026-10-14-core-1-followups.md) had grown to about 220 open-looking items, never sorted. Three triages checked every item against `main` at b8f006f and gave each a category and a fix:

- docs/reviews/2026-10-25-triage-C.md (C1–C100: core, policy, schema, routing)
- docs/reviews/2026-10-25-triage-G.md (G1–G76, R1–R10: GraphQL, API plans, and the 2026-10-20 reviews)
- docs/reviews/2026-10-25-triage-M.md (M1–M28, MS1–MS4, N1–N2: migrations, release, naming)

This spec rules on every item. Each one is either fixed in a wave, or deferred with a stated reason. The ids are those of the triage tables, which hold each item's evidence and proposed fix. Where a ruling below differs from a triage's proposed fix, the ruling stands.

The controller made every call (the user's standing delegation), following old velox and ent first, then the Go ecosystem.

## Goals

1. Every DEFECT is fixed.
2. Every API item is settled before 1.0, because 1.0 freezes exported names, signatures, generated-code shape and generated DDL names.
3. Every DOCS item is fixed.
4. TEST and PERF items are fixed when they are small or guard a promise. The others are deferred by name.
5. FEATUREs are built when they close a gap against ent/entgql that a porting user would hit, or when they are small and clearly right. The rest are deferred, each with its reason, in a "Deferred after 1.0" section that replaces the followups' open items.
6. The followups file ends with no unsorted item. Each item is resolved (citing its commit), deferred (citing this spec), or blocked on the user.

## Non-goals

- The pgx split (C53, G65, G38, G26). It is the next sub-project and keeps its own spec.
- Anything that needs the user's decision or a push. See "Blocked on the user".

## Rulings

### Naming parity with ent (frozen output)

1. **Inflection.** `plugin.Plural` and `plugin.Singular` use `github.com/go-openapi/inflect`'s default ruleset, as ent (entc/gen/func.go `ruleset()`) and old velox do. This fixes C21, C71 and C72: `person` → `people`, `children` → `child`, `DNS` → `DNSes` as inflect gives it, and `B2y` as inflect gives it. velox2 adds no rules beyond ent's. The plugin package's godoc says the rules are ent's.
2. **Default index names** are `<lower(type name)>_<cols>`, as ent's are (entc/gen/type.go:727). That fixes C77: an ent-created database baselines without index renames.
3. **Like keeps `string`** (C14), because a pattern is not a value of the column's type. The godoc says why.

### Generated-code shape (one bump: `GeneratedCodeIsVersion6`)

4. Struct-typed fields use `omitzero`, not `omitempty` (R1).
5. The `// Model: sha256:` header line is dropped (R2). `-check` already compares bytes.
6. Generated enums gain `String()` and `IsValid() bool` (R3). Go's form is `IsValid`, as in `netip.Addr.IsValid`.
7. `Desc.Tenant` uses 0 for "none" and stores column+1 (R9), so a zero `Desc` has no tenant. Its godoc says so.
8. MySQL's `MaxLen` cut-off for `varchar(n)` becomes `size <= 16381` (M10). The migrate spec's §4 and the goldens follow.
9. The single-key owner check is emitted as `EQ(k)`, not `In(k)` (G50).
10. velox's version constant becomes `GeneratedCodeIsVersion6`, replacing 5. veloxgql's becomes `GeneratedCodeIsVersion3`, replacing 2, if the GraphQL wave changes generated GraphQL code. It does: G45, G47, G48.

### Exported API

11. `Query.With[T]` and `Rel.With[U]` (G18, M28). Measure `entityDescUse` and the compile-cost rows with and without the methods. If the cost exceeds 1% of the entity-package bound, they become functions like `Sum`: `velox.With(q, rel)`. Otherwise they stay, and the api-cleanup spec records the measured cost as ruling 21's exception. The plan records the numbers.
12. **`WithTenant(ctx, id any)` keeps its signature** (C51). It converts an integer of any kind to the tenant column's integer type when the value fits, and a string kind to the column's string type. A value that doesn't fit, or a kind that can't be converted, fails with `ErrTenantMismatch` as now. The godoc says so.
13. **Policy.Insert keeps its signature** (C55). A policy that must see other rows uses a hook, through `Mutation.DB`, and the godoc on `Policy` says how. This is ent's split: privacy rules decide, and hooks query.
14. **`ConflictClause` carries no unexported field** (C42). The policy flag moves to the Statement's unexported state.
15. **A statement timeout joins the driver error** (C33): `errors.Join(timeoutErr, err)`, as the transaction timeout does.
16. **`ValidationError` and `ErrImmutable` both name the Go field** (C81).
17. **`Open` and `OpenShards` panic on an unknown or zero `Dialect`**, and `writer.pred` has a default case (C15).
18. **Mutation transactions** (G45). `gqlimpl.Atomic` uses `db.Tx(ctx, fn)`, which nests as a savepoint inside the extension's transaction. A resolver that swallows a mutation error then rolls back that mutation's writes only. `shared.OperationTxFromContext` is deleted if nothing else needs it. `TestNestedRequestBudget` is re-measured.
19. **Module path `contrib/graphql` stays** (R8). Renaming it to `contrib/veloxgql` would give `contrib/veloxgql/veloxgql`. ent's `entgql` lives under `entgo.io/contrib/entgql` as a single package, which is a different layout. The annotation package's name `graphql` stays, as the naming spec ruled. Its doc shows the import alias to use beside gqlgen's `graphql` package.

### Mutation semantics (contracts, decided now)

20. **G44.** A mutation returns the row as written. Its godoc and contrib/graphql's doc pin this as the contract: the UPDATE is Read-scoped, so the caller could read the row before writing it.
21. **G52.** An M2M link needs Read on the target, not Write, because it changes no target row. An O2M or O2O link writes the target's foreign key, so it needs Write, as now. Both rules are written in contrib/graphql's doc.
22. **G47.** Before an O2O re-point, a scope-free count finds the current child. If it is hidden from the caller, the mutation fails with BAD_USER_INPUT "already linked", and reveals nothing more.
23. **G48.** A delete also removes the join rows of one-sided M2M edges that point at the deleted entity.

### Defects fixed as the triage proposes

C20, C23, C25, C26, C27, C28, C29, C34, C35, C40, C47, C48, C49, C74, C75, C89, C97, C99; G3, G6, G9, G31; M1, M2, M3, M7, M8, M13 (message), M14, M22, M23; N1.

- **G31:** refuse non-ASCII plugin paths.
- **M9:** the normaliser stops matching across casts that can change meaning (interval casts, a `::timestamp` literal against a date column, `::text` on a column). It reports a difference instead. This keeps drift's rule that it never hides a real difference, and it needs no column types. The full typed normaliser is deferred.
- **M13:** full `BEGIN ATOMIC` support is deferred, since functions are a non-goal. The refusal names it.
- **M22:** `Index.Constraint` is a model field, filled by Inspect and baseline and carried in `schema.json`. Render emits `ALTER TABLE … DROP CONSTRAINT`, and the rename `ALTER TABLE … RENAME CONSTRAINT`, for it. This adds a field to `migrate`'s model before 1.0.

### Features built now (closing ent/entgql gaps, or small and clear)

- **G1:** the node key gets `id`, `idNEQ`, `idIn`, `idNotIn`, `idGT`, `idGTE`, `idLT` and `idLTE` where-input fields, as entgql's do. They are typed by the GraphQL ID and decoded with the type check.
- **G11, G12, G13:** enums of an application Go type are bound with `@goModel`, `@goModel` is refused as an application directive, and a test covers a renamed entity.
- **G4, G29, G30, R4:** velox-gen error UX:
  - the `go get -tool` hint;
  - the user's line rather than velox2's mixin line;
  - the panic stack under `VELOX_PLUGIN_TRACE=1`;
  - "did you mean" for `Ref` and index names.
- **G24:** `Cost` evaluates `@skip` and `@include`.
- **G37:** `ErrorPresenter` takes variadic options now, starting with `OnCanceled`, so adding more later is not a break.
- **G70:** `ErrLocked`, matched from PostgreSQL 55P03 and MySQL 3572.
- **C87, G53:** `TxInfo` gains the route: namespace, server and shard. veloxotel reads it.
- **C19, C22:** velox-gen verify's temp-dir sweep and signal handling, and the build-failure explanation.
- **M4, M5:** MySQL introducers on ASCII literals are stripped, and `Tables` refuses a default the column would round.
- **G49, G51:** gogen/mutation.go is factored (the goldens unchanged), and the generated godoc points to contrib/graphql's doc instead of repeating it.

Each item is additive or internal, so doing it after 1.0 breaks nobody:

- M11, M12 (internal refactors);

## Constraints

- Go 1.27.

- Commits end with the repository's trailer. No push.
