# Decisions

Each record is a binding decision of velox's design, with its context, its
consequences and where it is enforced: a test, the code, or the spec line it
came from. The specs in [docs/history/specs](../history/specs/) and the plans in
[docs/history/plans](../history/plans/) hold every ruling; these are the ones a user or a
contributor needs to know.

| Record | Decision |
| --- | --- |
| [0001](0001-ent-names.md) | Tables, columns, indexes, constraints and inflection follow ent's, so an ent database baselines without renames. |
| [0002](0002-no-inflect-dependency.md) | Plural's rules are copied from go-openapi/inflect v0.19.0 into the stdlib-only plugin package, and the naming helpers' outputs never change within a major version. |
| [0003](0003-nullability.md) | Optional stays NOT NULL, as in veloxe; Nillable makes a column NULL-able. |
| [0004](0004-versioning.md) | Semantic versioning from 1.0, except generated code: its version constant is replaced in a minor release; schema.json and velox.json read older versions and refuse newer ones. |
| [0005](0005-deprecation.md) | Nothing is deprecated before 1.0; after 1.0, `// Deprecated:` until the next major version. |
| [0006](0006-own-migrate-and-atlas.md) | velox keeps its own planner and ships `migrate sql` for Atlas; a directory is managed by one of them. |
| [0007](0007-policies-decide-hooks-query.md) | Policies decide from the context and the row; a rule that must see other rows is a hook. |
| [0008](0008-write-policies-filter.md) | A Write policy filters: a write to rows it hides affects 0 rows, not an error. |
| [0009](0009-mutations-return-as-written.md) | A GraphQL mutation returns the row as written; a many-to-many link needs Read on the target, a link from the owner that sets its key Write. |
| [0010](0010-savepoint-per-mutation.md) | Superseded by 0045. Each GraphQL mutation runs in a savepoint of the operation's transaction. |
| [0011](0011-bidirectional-edges.md) | A self edge with no inverse is bidirectional, as in ent: links and unlinks write both directions. |
| [0012](0012-drift-never-hides.md) | Drift never hides a real difference, except a cast whose meaning depends on the column's type. |
| [0013](0013-version-floors.md) | migrate needs PostgreSQL 14, MySQL 8.4 or SQLite 3.35. |
| [0014](0014-with-stays-a-method.md) | Query.With and Rel.With stay methods: as functions they would save 1638 bytes, under 1%. |
| [0015](0015-contrib-graphql-path.md) | The module path stays contrib/graphql, imported as `vgraphql` beside gqlgen's graphql. |
| [0016](0016-withtenant-converts.md) | Superseded by 0029: `WithTenant` converted a predeclared integer or a string to the tenant column's type. |
| [0017](0017-upsert-skips-updatedefault.md) | An upsert's update branch does not fire UpdateDefault, as in veloxe and ent. |
| [0018](0018-pgx-stdlib-scan-wrapper.md) | On pgx's stdlib driver, scans go through a sql.Scanner, so pgx's per-column type check passes at its first step: 81% less time for a 100-row query with time columns (the before and after runs had different loads). |
| [0019](0019-veloxpgx.md) | pgx's native path is the package veloxpgx in this module; the core reads pgx's errors by type name, so it links no driver. |
| [0020](0020-root-and-engine.md) | The root package is the generic API and `internal/engine` is the rest: the root's `DB` holds an `engine.DB`, its public names are aliases, and each test lives by the code it tests. |
| [0021](0021-veloxtype.md) | The plain data types are in the public package `veloxtype`, which the root re-exports, so their fields and methods have real documentation; what reaches a private field stays in the engine. |
| [0022](0022-group-by.md) | Grouped aggregates take `handle.Key()`, a generic method, since an ordinary method or a phantom field costs every entity package; a group list obeys `AllowUnbounded()` and the row cap; NULL keys are nil, NULL sums 0, and an empty group has no average, least or greatest. |
| [0023](0023-module-path.md) | The module is `github.com/syssam/velox`; the earlier project is veloxe, and its tags are never reused |
| [0024](0024-public-surface.md) | The public API is pinned by a snapshot; `migrate.Change` is opaque; `internal/engine` exports only what crosses it |
| [0025](0025-connect.md) | `velox.Connect` opens a database in one call; `DB.Close` closes only what it opened; `velox.Pool` is the `*sql.DB` under it |
| [0026](0026-migration-safety.md) | `Up` refuses to destroy what the model cannot hold: a SQLite rebuild and a MySQL `MODIFY COLUMN` are checked against the database at apply time, and `-- velox:allow unmodeled-loss` accepts the loss. |
| [0027](0027-graphql-limits.md) | The cost charges statements and introspection's response; a Required edge is nullable; the generator refuses what could only fail later; an explicit zero value on a Default is refused in GraphQL and stays unset in the core |
| [0028](0028-runtime-edges.md) | The runtime's edges fail or say so: After needs its order columns selected, a nested Tx's error means its work is undone, SQLite enforces TxReadOnly and writes velox's time form, a statement inside Iter on a pool of one fails rather than hang, a MySQL deadlock breaks its transaction |
| [0029](0029-scope-replaces-tenant.md) | The core has no tenant: a scope is a `Policy` plus a hook from `velox/scope`, `WithoutPolicy` lifts it, the scope column is `Immutable`, and `WithShardFor` reads the context. |
| [0030](0030-generated-scope.md) | Superseded by 0038. A scoped column is marked `schema.Scoped(key)` in the schema; velox-gen writes the key (`OrgKey`) and each entity's scope into `scope_velox.go` and binds it around the entity's own `Policy` and `Hooks`, so it cannot be dropped. |
| [0031](0031-to-one-joins.md) | A query joins a to-one relation (`Join`, `LeftJoin`): the related entity is filled from the same row, `rel.Is` and `rel.By` filter and order by its columns, and the target's Read policy is in the ON clause. A to-many relation is refused. |
| [0032](0032-ent-refusals.md) | What ent users write is generated: a zero Default, graphql.CreateDefault for a non-zero one, an OrderField on a nullable field with NULL last on every dialect, JSON lists as GraphQL lists; a Uint64 over 2^63-1 says why it is refused |
| [0033](0033-graphql-inputs-not-mutations.md) | Methods, runtime and nulls superseded by 0045. velox-graphql generates `Create<T>Input` and `Update<T>Input` with their methods `Create(ctx, x)` and `Update(ctx, id, set...)`, run by a generic gqlimpl runtime, and no `type Mutation` and no delete: the application declares its mutations, as with entgql. |
| [0034](0034-schema-declares-behaviour.md) | Superseded by 0039 but for the schema declaring behaviour and gen being all generated. An entity's `Policy` and `Hooks` are declared on its schema, typed with gen; velox-gen writes `gen/runtime` to bind them, an entity fails at first use when it is not linked, and the loader compiles the schema without them, so `gen/` is all generated and a stale one never blocks generation. |
| [0035](0035-untyped-runtime-for-generated-graphql.md) | Generated read surface revised by 0046. Generated GraphQL code runs on a non-generic gqlimpl over velox's untyped `Table` surface, "For generated code.", which builds the typed API's statements through the same engine and refuses another entity's conditions, rows and out-of-range values; a 100-entity `gen` compiles in 1.7 s instead of 7.2 s. |
| [0036](0036-split-gen-for-behaviour.md) | Layout superseded by 0037. A schema with `Policy` or `Hooks` splits gen: `gen/entity` holds the entities and does not import the schema, which imports it; `gen` re-exports every name and binds the schema in its `init`, so a program imports gen alone. `gen/runtime` and its blank import are gone; `gen/entity` alone fails at first use, and a schema that imports gen is refused. Revises 0034. |
| [0037](0037-ent-layout.md) | gen/runtime half superseded by 0039. ent's layout: every entity is in `gen`, always, with no `gen/entity` and no aliases. A schema that imports gen is not imported by it: `gen/runtime` binds its methods, defaults and validators by name, and a program imports it once, `import _ ".../gen/runtime"`, as ent's `ent/runtime`; without it a statement fails and names that line, and velox-gen warns of a module with no such import. gen/runtime is written only when something needs binding; the schema may not import it. Supersedes 0036's layout. |
| [0038](0038-tenancy-is-a-mixin.md) | Revised by 0039. Tenancy is a mixin the application writes over package `scope`, bound before the entity's own; `schema.Scoped`, `scope_velox.go`, `Descriptor.Scope` and `velox.Scoper` are gone, and `scopetest.Isolates` checks an entity is confined. Supersedes 0030. |
| [0039](0039-untyped-behaviour.md) | Revised by 0040. Behaviour declared in the schema is untyped and names columns by name (then `velox.C("org_id").EQ(v)`, `velox.Edge("doc").Has()`), as ent's is; mixin methods are plain; gen imports the schema (then as `sch`, listing method values); the schema may not import gen; gen/runtime is gone; a hook that needs gen's types is a run-time `velox.WithHooks`. |
| [0040](0040-schema-value-and-ent-names.md) | A descriptor names its schema's value, `Schema: schema.Issue{}`, and velox reads the mixins' and the schema's Policy, Hooks and Interceptors from it; gen imports the schema by its own name; conditions take ent's names (`velox.FieldEQ`, `velox.HasEdge`, `velox.HasEdgeWith`) over one `velox.Predicate`, an instance of `Pred`. Revises 0039. |
| [0041](0041-edges-struct.md) | An entity's relations are in an ent-style `Edges XEdges` struct, `json:"edges,omitzero"`; One and Many keep the loaded state, so there is no `loadedTypes` and no per-edge `OrErr`; `XEdges` joins velox-gen's top-level name check. |
| [0042](0042-plain-file-names.md) | An entity's generated file is `<entity>.go`, as ent names it, or `<entity>_velox.go` when go build would leave that name out of a build (`ab_test.go`, `server_linux.go`) or it is `velox.go`; velox-graphql's files keep `_gql.go` |
| [0043](0043-graphql-method-names.md) | velox-graphql names an edge's method after the edge (`Post.Author(ctx)`) and a Node's ID method `GlobalID`, as entgql's are; the SDL drops the `@goField` gqlgen no longer needs; no per-type `NodeGQL` or `KeyGQL`. Its Node and `GlobalID` are superseded by 0061 |
| [0044](0044-edge-setters.md) | A relation handle's `Add`, `Remove` and `Clear` are `Setter`s that `Insert` and `Update` write after the row, in one transaction, with gqlimpl's edge semantics moved into the core; a failure on keys is a `*velox.EdgeError` of `ErrNotFound` or `ErrLinked` |
| [0045](0045-graphql-input-setters.md) | A GraphQL input has one method, `Setters()`, plain Go that returns velox setters with no I/O; the resolver writes them with `db.Insert` or `db.Update` and reads the row back; an explicit null is a field not given; gqlimpl keeps only what Setters calls |
| [0046](0046-graphql-paginate.md) | A type's connection is `Paginate<Plural>(ctx, q, …)` of a query the resolver builds, as entgql's `Query().Paginate`; a where input's untyped condition is unexported; `gqlimpl.Conn` is `gqlimpl.Type`, described by `postGQL` |
| [0047](0047-graphql-edge-source.md) | An edge method is one line: `(*gqlimpl.Type).Edge(x, rel)` passed to `EdgeOne`, `EdgeList` or the target's unexported `paginate<Plural>`, which `Paginate<Plural>` calls with `gqlimpl.Query(q)`; `Type.Edges` is by relation and names the field; a batch keys on the arguments Paginate got, `Args.Where` but not `Args.Pred` |
| [0048](0048-update-one.md) | `UpdateQuery.One` writes the one row its conditions match, under the Read and Write policies, and returns it read back by its key, as ent's `UpdateOne`; `veloxgql.DB(ctx)` panics where `DBFromContext` fails; `Setters()` keeps its error |
| [0049](0049-graphql-go-names.md) | A connection is `NewPostConnection(ctx, q, …)`, lazy, and its body has no plumbing (`Args.Order`, `gqlgraph.WhereOf`); the runtime is `veloxgql/gqlgraph`, after ent's `sqlgraph`; `postType`, `Column{Name, Index}`, `AlwaysRead`, `EdgeIDField`, `Validate`, `nodeKind`; receivers are named after their type |
| [0050](0050-handles-enum-haswith.md) | The handles' type is exported, `PostHandles`; an enum's handle is `velox.Col` (no Contains or Like); `Rel.HasWhere` is `Rel.HasWith`, as ent's `HasXWith` |
| [0051](0051-untyped-rows-are-any.md) | The untyped surface takes and returns a row as a *E in an any, checked against the Table's entity, not an unsafe.Pointer; `Table.Ptr` is gone; gqlgraph and gqlcore hold rows as any; the aggregates stay functions, as methods cost each entity package about 30 KB. Revises 0035 |
| [0052](0052-untyped-package.md) | The untyped surface is package `velox/untyped` (`untyped.TableOf`, `untyped.Query(db, t)`, `untyped.FromQuery(q)`, `untyped.MutationTable(m)`…); `velox.Meta` and `velox.Query` hold engine state that it reaches by a pointer conversion; `Typed` is gone; veloxgql Version19. Revises 0035 and 0051 |
| [0053](0053-engine-split.md) | `internal/engine` keeps its name; the drivers' errors are `internal/dberr`; rendering and routing stay, as `EntityInfo`, `Statement` and `Node` hold engine state. Amends 0020 |
| [0054](0054-fail-closed-runtime.md) | The runtime fails closed: `db.WithoutPolicy(reason)` returns a DB, and the context form is gone; a GraphQL edge batch is keyed by the SQL each caller's context reads; a pool's one connection is held by its Iter's or Tx's context, not a goroutine ID. Amends 0028 |
| [0055](0055-lazy-unsafe-scope.md) | `[_ Lazy[E]]` stays: without it one `Query[E]` adds 76× the bytes to a package and an entity package 3.1×; `unsafe` stays, with offsets from `fieldOf` and `-race`'s checkptr; routing and migrate stay, free for a DB that does not use them |
| [0056](0056-scale-round.md) | Keys of any type are tested on every dialect; `field.Int64("version").Version()` gives optimistic locking with `ErrStale`; overload, COPY, resharding, MySQL online DDL and an outbox stay outside velox; CockroachDB is not supported (NULL order) |
| [0057](0057-column-subqueries.md) | A column handle's `Select(ps...)` is a `Subquery[V]` that another handle of the same type tests with `InSelect` or `NotInSelect`; it is the EXISTS `HasWith` writes, correlated on two columns, so the target's policy and interceptors apply; `NotInSelect` is `NOT EXISTS`, safe with NULLs |
| [0058](0058-json-paths.md) | A JSON handle's `Text(keys...)`, `Number(keys...)`, `Bool(keys...)` and `HasKey(keys...)` read one kind of value at a path, NULL for any other, with each dialect's type test, so the same rows match on PostgreSQL, MySQL and SQLite; keys are arguments |
| [0059](0059-query-paginate.md) | A connection is `db.Query[gen.Post]().Paginate(ctx, after, first, before, last, gen.WithPostOrder(o), gen.WithPostFilter(w))`, ent's call: a generic method whose cursor, option and connection types Go infers from the entity's generated `PaginateQuery`; `NewPostConnection` is gone |
| [0060](0060-raw-rows.md) | `db.Rows(ctx, reason, sql, args...)` yields rows that are no entity's, to `Scan` in column order, on the DB's connection, a transaction's included, as `Raw`'s `Iter` runs |
| [0061](0061-graphql-plain-ids.md) | A GraphQL ID is the entity's key in its own Go type, which gqlgen decodes (`id int64` in a resolver), one key Go type per schema; `veloxgql.Int64ID` is the int64 ID; no Node, `node`, `nodes`, `GlobalID` or `DecodeID`; cursors stay opaque |
| [0062](0062-set-input.md) | `UpdateQuery.SetInput(in)` and `InsertQuery.SetInput(in)` take a `velox.Input[E]`, such as a generated GraphQL input, as ent's `SetInput` does; an error from `Setters()` is kept and returned unchanged by `Exec`, `One` or `SQL` before anything is sent; generated `Setters` has a value receiver (veloxgql Version22) |
| [0063](0063-optional-needs-a-value.md) | An `Optional` field that is not `Nillable` has a `Default` or `DefaultFunc` (a `SchemaDefault` alone no longer counts, amended 2026-11-13), or velox-gen refuses it (rule 37 for every type); an unset field no longer writes the Go zero value and the planner no longer gives its column a zero `DEFAULT`; `Optional().Default("")` is the empty string |
| [0064](0064-insert-null-literal.md) | A nullable column that every row of an INSERT leaves NULL is written as the literal `NULL`, not a parameter per row; the column is still written, so a `DEFAULT` does not apply, and the shape key holds which columns are literal; 100 rows of 25 columns with 13 nil send 1,200 parameters, not 2,500, and run in 0.72 ms, not 1.03 ms, on PostgreSQL |
| [0065](0065-veloxgen-veloxschema-defaults.md) | `velox-gen` with no flags reads `./veloxschema` and writes `./veloxgen`, a package named `veloxgen`, not `./schema` and `./gen`: both old names clash with other packages a program holds; `-out` and `-package` still name any other; the generated code's shape is the same, so `GeneratedCodeIsVersionN` stays |
| [0066](0066-use-tx.md) | `vtx, err := velox.UseTx(db, tx)` returns a DB on a `*sql.Tx` the caller began, a function so `*sql.Tx` stays out of `DB`'s method set: the caller commits or rolls back and the DB fails once `tx` ends, nothing is retried and no `TxAround` hook runs, a nested `Tx` is a savepoint; veloxpgx and a sharded DB are refused |
| [0067](0067-allow-unbounded.md) | A read with no `Limit` is allowed by `AllowUnbounded()`, not `Unbounded()`: no popular Go ORM has a read guard or the word; gorm names its write opt-out `AllowGlobalUpdate`; the call only waives the check, so a `Limit` still applies; `ErrUnbounded` and `Statement.Unbounded` keep their names. Amends 0022 |
| [0068](0068-graphql-enums-only.md) | `velox-gen -plugin velox-graphql:only=enums` writes only the `MarshalGQL` and `UnmarshalGQL` of velox-gen's enum types, for an application with its own SDL and gqlgen autobind: `open` goes out as `OPEN` and comes back as `open`; no `velox.graphql`; the marshalers stay out of velox-gen, as `graphql.EnumValues` renames are GraphQL's |
| [0069](0069-expr.md) | `velox.Expr[E](text, args...)` is SQL text as one more `Where` condition, so the Read policy, scope and interceptors still apply, unlike `Raw`; a column handle fills a `?` as the column, any other value is bound; text with a quote, `;`, a comment, an unbalanced parenthesis or SELECT, WITH, TABLE, VALUES, UNION and the like is refused, so a subquery is `HasWith` or `InSelect`; not ent's `Modify`, which needs an exported SQL builder; a guard against a mistake, not hostile text |
| [0070](0070-index-method.md) | `sqlschema.IndexType("GIN")` on an index (first a builder method `.Method("gin")`, see 0075) sets its PostgreSQL access method (btree, hash, gin, gist, spgist, brin); PostgreSQL only, refused on MySQL and SQLite; btree is no method; a unique index is btree; a GIN index may cover a JSON field; `Inspect` reads the method instead of noting it; operator classes, DESC and INCLUDE stay unheld |
| [0071](0071-graphql-resolvers.md) | `graphql.Resolvers(graphql.Map(field, type).WithComment(text))` on a schema adds fields to its GraphQL type that the application's resolvers answer, written with `@goField(forceResolver: true)`, as the old velox spelled it (nextapp calls it 296 times, for keys of types its own SDL declares); the type may be the application's own, so `Render` leaves mapped fields out of its standalone check; a selection that holds one reads every column, as an extend type's field does; `Loads` and `Reads` are not taken. Amends the 2026-10-19 design |
| [0072](0072-index-desc-opclass.md) | `sqlschema.DescColumns(names...)` and `sqlschema.OpClassColumn(name, class)` (first builder methods `.Desc` and `.OpClass`, see 0075), PostgreSQL only; names resolve to columns, `Desc` needs a btree index, a class is a name (rules 60 to 62); they are part of an index's identity and a change is a drop and create built beside the old; `Inspect` reads DESC and any class that is not its type's default, instead of noting them; the guard knows them (`key-options`); extension classes need the extension added to the baseline by hand. Completes 0070
| [0073](0073-db-default.md) | `sqlschema.Default("100")` on a field (first a builder method `DBDefault`, see 0075) is `SchemaDefault` with one SQL text for the three dialects, `DefaultExprs` one for each; velox-gen refuses a MySQL `SchemaDefault` that is a literal on a text, blob or JSON column, which MySQL takes only as an expression |
| [0074](0074-projection.md) | `Query.Select`, `SelectRaw`, `GroupBy`, `Having` and `Rows` read terms (column handles, `Calc`, a handle's `Sum`, `Count` and the like) in place of an entity, with several keys, `HAVING` and an ordering by an aggregate or an expression; it is a read of E, so the Read policy, scope and interceptors still apply, unlike `Raw`; one `Term` is a result column, a key, an `Expr` operand and an ordering; rows are read by position; no `All`, `Join`, `With` or `After` on it |
| [0075](0075-sqlschema-annotations.md) | SQL-only options are annotations of package `dialect/sqlschema`, with the old velox's names, not builder methods: `IndexType`, `IndexTypes`, `IndexWhere`, `Desc`, `DescColumns`, `OpClass`, `OpClassColumn` on an index and `Default`, `DefaultExpr`, `DefaultExprs` on a field, because one schema feeds SQL, GraphQL and later gRPC; the loader lowers them into the values the existing rules read; `StorageParams`, `Prefix`, `PrefixColumn` and `IncludeColumns` compile for a port and are refused; `.Method`, `.Desc`, `.OpClass` and `DBDefault`, all unreleased, are removed |
| [0076](0076-root-schema-types.md) | package `dialect` names `Postgres`, `MySQL` and `SQLite`, and package `velox` declares `Schema`, `Field`, `Edge`, `Index`, `Mixin` and `Annotation` as aliases of package `schema`'s, as ent's root and the old velox's did, so a port compiles them with no edit; the same types, so discovery and generation are unchanged; the 2026-11-04 rejection of a facade was about generated code |
| [0077](0077-graphql-port-spellings.md) | The old velox's graphql spellings: `QueryField()` names the entity as it did (`terms`, `graphQlLogs`), `RelayConnection()` says nothing, `OpsNone` is no predicate, `WhereInput()`, `EnableWhereInputs(true)` and `WhereInputEdges` are `WhereOps()` and `WhereEdge()`, `NewDirective` and `Deprecated`; `OpsJSONArray` was left out here and is done by 0080, `OpsCaseFold` by 0078 |
| [0078](0078-case-folding-text-predicates.md) | `ContainsFold` and `FieldContainsFold` beside `EqualFold`; velox-graphql has `OpEqualFold`, `OpContainsFold`; `OpsString` and `OpsComparison` mean the old velox's and `WhereOps()` on a string offers `OpsString`; the cost model charges the folds as scans |
| [0079](0079-field-in-select.md) | `velox.FieldInSelect(column, entity, key, ps...)` is the by-name subquery on another entity, for the schema's Policy, Hooks and Interceptors: the `EXISTS` that `InSelect` writes, so the target's Read policy applies inside; resolved at statement preparation, a wrong name or type an error, never a dropped arm; velox-gen reads the constant entity, checks the names and writes `Descriptor.Links` (`LinkEntity`); `GeneratedCodeIsVersion21`; no `privacy` package |
| [0080](0080-json-array-elements.md) | `Has`, `HasSome`, `HasEvery` and `IsEmpty` on a JSON handle, alike on PostgreSQL, MySQL and SQLite: an element is a string, a number or a boolean, `true` is not 1, a document that is no array holds none and is not empty, a NULL column is NULL; `@>` stays a conjunct for a GIN index; `OpsJSONArray` in velox-graphql, offered by `WhereOps()` on a `[]string`, `[]int`, `[]int64`, `[]float64` or `[]bool` field, the four charged as scans; `GeneratedCodeIsVersion24` |
| [0081](0081-entity-table.md) | One `velox.EntityTable` per generated package with behaviour, which every descriptor names: `HasEdge`, `HasEdgeWith` and `FieldInSelect` find their target in it when the statement runs, an entity by its name or its table, so a rule in a shared package can take its names from configuration; velox-gen checks constant names and warns about the others; `velox.Linked` and `Descriptor.Links` are gone; `EntityLink.Type` is a string, as a `reflect.Type` cost 140 KB per generic type; `GeneratedCodeIsVersion22` |
| [0082](0082-defaults-before-setters.md) | An insert fills defaults before its setters and hooks, as ent does, so a setter or `Mutation.Set` stores false, 0 or "" over a default; any `Default` or `DefaultFunc` on a bool or number is allowed (`field.Bool("x").Default(true)` ports from ent, `NOT NULL DEFAULT true`); rule 36 and `ColumnDescriptor.ZeroInvalid` are gone; `GeneratedCodeIsVersion23` |
| [0083](0083-package-index-names.md) | `schema.Package`, one exported variable in the schema package, holds its options for every velox-gen command: `PrefixIndexNames` names each index `<table>_<name>` unless it starts with `<table>_` (veloxe applications' hook), and `Names: schema.VeloxeNames` caps long names with veloxe's FNV-1 128 suffix instead of ent's MD5; loadjson Version 7 |
| [0084](0084-constraint-names-per-table.md) | Check and not-null names are compared with their own table's constraints, as PostgreSQL keeps them; foreign keys across the database too; MySQL's `Tables` refuses a check name another table has as a check or foreign key |
| [0085](0085-self-one-to-one-key-on-assoc.md) | A one-to-one pair to its own schema whose assoc edge alone binds the key field keeps the key in the assoc edge's rows (`Edge.KeyOnAssoc`), as veloxe schemas declare it; each edge reads from its own end |
