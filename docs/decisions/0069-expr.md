# 69. Expr is SQL text that keeps the policies

Status: accepted, 2026-11-18.

## Context

A query the builder cannot say went to `Raw`, `Rows` or `Exec`, and those
skip every Read policy, scope and interceptor (0060, the guide's Raw SQL).
One custom clause, such as `LOWER(name) = ?` or `EXTRACT(YEAR FROM at) = ?`,
cost a caller all of them.

ent keeps them with `Modify(func(*sql.Selector))`: the modifiers run first,
then the policy's predicates are applied to the selector (`query.tmpl`: the
selector template, then `for _, p := range q.predicates`). The policy
survives by order, and the caller gets the whole SQL builder. velox has no
SQL builder to hand out: a statement is a `Statement` that is rendered
through a shape-keyed cache, and a policy is a `Where` node.

## Decision

- `velox.Expr[E](text, args...)` is a `Pred[E]`: one more condition, so
  `Where` ANDs it with the policy, the scope and the interceptors' conditions,
  as it does any other. It renders as `(text)`.
- Each `?` in text is filled by the next argument: a column handle of E is
  written as the column, qualified as any condition's is; any other value is
  bound, in the dialect's placeholder, as given (no codec).
- The text is refused, when the statement runs and before anything is sent,
  if outside a string literal it holds a quote, a backtick, `;`, `\`, `$`,
  `#`, `--`, `/*` or `*/`, a control character, an unbalanced parenthesis, or
  one of SELECT, WITH, TABLE, VALUES, UNION, INTERSECT, EXCEPT, INTO,
  RETURNING, PRAGMA, ATTACH, in any case. So text cannot end the condition or
  start a subquery that reads a table without that table's policies; another
  table is `HasWith` or `InSelect` (0057).
- A string literal is `'x'` where x holds no quote, backslash, `?` or control
  character. Where a literal ends differs by dialect when it may hold a
  backslash (MySQL, and PostgreSQL's `E''`) or a doubled quote, and a scan
  that guessed wrong would take a `SELECT` for data. With neither allowed, its
  end is the same everywhere, and what is inside is data that the scan skips.
  A literal that needs more is an argument (`ESCAPE ?`, not `ESCAPE '\'`).
  nextapp's real fragments need them: 85 of its SQL fragments hold `''`,
  `'_'`, `'[]'::jsonb` or `'$.employee_id'`.
- FROM is allowed: EXTRACT, TRIM and SUBSTRING use it, and without one of the
  banned words it starts no subquery.
- A wrong count of `?`, a handle of another entity (found by its type: a
  struct of this package with a column index `I`), and an encoded (JSON)
  column are errors, as a zero `Pred` is.
- The render cache keys the text pieces and which slot holds which column;
  the values are arguments, so one shape serves every value. A bidirectional
  join entity's swap of columns 0 and 1 covers an Expr's columns.

## What this does not guard

The refusals catch a policy bypass by mistake. They are not a defence against
hostile text, which an application never takes from a user: a function that
runs SQL from a string argument (PostgreSQL's `query_to_xml`) still would.
The words are matched without a parser, so a legitimate function named like
one of them (`VALUES`, `TABLE`) cannot be called, and `WITH TIME ZONE` is
written `AT TIME ZONE` or `::timestamptz`. A PostgreSQL `?` operator is
written as its function, `jsonb_exists`.

## Rejected

- ent's `Modify`: it needs an exported SQL builder, which is a large public
  surface kept for good, and it would leave the render cache and the Rewrite
  hooks' view of the statement.
- Allowing a subquery in the text and adding the target's policy: it needs a
  SQL parser to find the tables.

## Not in this record

`OrderExpr`, multi-key `GROUP BY` and `HAVING`, and CTEs or windows with the
policy applied are not built. `After` and `Paginate` read an order term by
column index, so an expression order needs its own refusals there.

## Evidence

`TestExprRefused` (each refusal above), `TestExprRenderCache`,
