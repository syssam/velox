# API Plan 2: Schema DSL, velox-gen and Plugin Protocol 2 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the schema side ready for 1.0:
- one frozen set of naming helpers;
- a small `schema/load`, and errors with `file:line`;
- an exported, typed DSL that refuses contradictions;
- `edge.OnDelete`;
- plugin model 2 and protocol 2, with `plugin.Main`;
- a velox-gen CLI with subcommands, `version` and exit code 3.

**Architecture:** Each task changes one part of the schema side and moves every caller in the same commit: the DSL, `internal/gen`, `cmd/velox-gen`, `plugin`, velox-graphql, examples, the testmodel and docs. Model 2 and protocol 2 are separate tasks, and velox-graphql moves with each. The repository builds and passes the full gate after every task.

**Tech Stack:** Go 1.27; no new dependency. Package `plugin` stays standard-library-only.

**Spec:** `docs/specs/2026-10-20-api-cleanup-design.md`, §3.3–3.6. §3.1 and §3.2 are done (API plan 1). The evidence is `docs/reviews/2026-10-20-api-review-schema.md` (findings 3–14, 17) and `docs/reviews/2026-10-20-api-review-contrib.md` (the plugin side), plus the "Left by API plan 1" lines for plan 2 in `docs/plans/2026-10-14-core-1-followups.md`.

## Global Constraints

- **No aliases.** No renamed or removed API keeps an alias or a deprecated copy. Every caller moves in the same commit: `schema/*`, `internal/gen`, `cmd/velox-gen`, `plugin`, `contrib/graphql` (with its goldens), `example/*`, `internal/testmodel`, `internal/itest`, `bench/scale` and every doc snippet.
- **Generated code stays at `GeneratedCodeIsVersion4`.** This plan changes generated code only compatibly (Ruling 18). A task that finds an incompatible change stops and reports it.
- **Plugin protocol 2 and model 2.** `plugin.ProtocolVersion = 2` and `plugin.ModelVersion = 2`. A plugin written for protocol 1 gets an error that names it and says to update it.
- **`plugin` imports only the standard library** (`TestPluginPackageImportsNothing`).
- **Budgets and escape check unchanged.**
  - `go test -run Budget -v .`: one-row 6, tenant 7, hundred rows 105, tx 9/6, observed 7/6, metadata 19, Insert 13, replica one-row 6.
  - `go build -gcflags=-m . 2>&1 | grep "db.go:$(grep -n 'func (db \*DB) plain' db.go | cut -d: -f1):"` prints `leaking param content: st` and `read does not escape`.
  - This plan does not touch the core. A task that moves a number stops and reports it.
- **Deterministic output.** Generated files, `velox.go`'s model hash and `describe` output never depend on the machine, the checkout path or the order of the arguments.
- **The full gate passes at every task's commit:** `<scratchpad>/fix1.sh`, with Docker. If golangci-lint's lock is held, run it with `--allow-parallel-runners`.
- **CI.** `scripts/ci-local.sh` and `.github/workflows/ci.yml` stay identical in what they run.
- **No machine-specific paths** in committed files. Committed text says `<scratchpad>`.
- **Shell only:** `GOCACHE=<tmp>/velox2-gocache GOFLAGS=-p=2`. The machine is short of memory: one heavy command at a time. Do not kill other processes.
- **Commits** end with a blank line and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push.

## Review Focus

1. **Machine paths in the output.** Positions are absolute paths. They must never reach a generated file, `velox.go`'s model hash or `describe -json`. Otherwise `-check` fails on every other checkout. Task 2 pins this: the same schema in two directories gives byte-identical output.
2. **Nested plugin paths.** These must fail before anything is written: `../x.go`, `/x.go`, `a//x.go`, `a/./x.go`, `a\x.go`, and `pb/X.go` next to `PB/x.go` (case-folded over the whole path). A stale-file sweep never deletes a file without the header, never enters `.git` or `.velox-verify-*`, and never removes a directory it did not empty. Task 7 pins this.
3. **Old plugin, new velox-gen.** A plugin built against protocol 1 must fail with `plugin velox-graphql: it speaks plugin protocol 1 (or does not say); velox-gen speaks 2: update the plugin`. It must not fail with a JSON error, or with no error and no files. Task 7 pins this with a fake plugin that answers in protocol 1's shape.
4. **Typed constructors equal their ent spellings.** `field.Number[Cents]("p")` and `field.Int64("p").GoType(Cents(0))` must load to the same JSON. So must `field.EnumOf[Status]("s")` and `field.Enum("s").GoType(Status(""))`, and `field.UUIDOf[uuid.UUID]("id")` and `field.UUID("id", uuid.UUID{})`. Their generated code must be identical too. Task 3 pins this.
5. **The rerun command with plugin options.** `-check` prints the command to run. With `-plugin 'velox-grpc:go_package=x/pb'`, that command must be copy-pasteable into a POSIX shell, quoted where needed. Task 7 pins this.

**Interfaces:**
- **Exported builder types.** `field.BoolBuilder`, `NumberBuilder[T]`, `StringBuilder`, `BytesBuilder`, `TimeBuilder`, `UUIDBuilder`, `JSONBuilder`, `OtherBuilder` and `EnumBuilder`; `edge.AssocBuilder` and `edge.InverseBuilder`. The embedded `common[B]` and `typed[B, V]` stay unexported. go/doc lists their methods under each builder.
- **Numbers.**
  - `type Numeric interface{ ~int | ~int8 | ~int16 | ~int32 | ~int64 | ~uint | ~uint8 | ~uint16 | ~uint32 | ~uint64 | ~float32 | ~float64 }`.
  - `func Number[T Numeric](name string) *NumberBuilder[T]`. When `T` is a named type, it sets the GoType as `GoType(T(0))` does, and `Type` is T's kind. `Validate`, `Default`, `Min` and the rest take `T`.
  - `Int` through `Float32` return `*NumberBuilder[<builtin>]`.
  - `Float64` is removed. `Float` is the float64 constructor, as in ent.
- **Enums.**
  - `func EnumOf[T interface{ ~string; Values() []string }](name string) *EnumOfBuilder[T]`.
  - It is `Enum(name).GoType(T(""))` with `Default(v T)`. `EnumOfBuilder[T]` embeds `common[*EnumOfBuilder[T]]`.
- **UUIDs.**
  - `func UUIDOf[T driver.Valuer](name string) *UUIDOfBuilder[T]`.
  - It is `UUID(name, zero T)` with `Default(fn func() T)`.
  - `UUID(name, typ).Default(fn any)` stays, for ent ports.
- **Time.**
  - `func (b *TimeBuilder) Default(fn func() time.Time) *TimeBuilder`.
  - `func (b *TimeBuilder) UpdateDefault(fn func() time.Time) *TimeBuilder`.
  - With a GoType, the builder fails unless the GoType converts from `time.Time` (`reflect.Type.ConvertibleTo`). The generated default then converts: `T(fn())`.
- **Defaults on the other builders.** `DefaultFunc` and `UpdateDefault` on `typed` keep taking `any` (Ruling 6).
- **Bytes.** `BytesBuilder.MaxLen(n)` sets `Size = n`, as `StringBuilder.MaxLen` does.
- **Dialect keys.**
  - `const ( Postgres = "postgres"; MySQL = "mysql"; SQLite = "sqlite" )` in `field`. They equal the core's dialect names in `dialect.go`.
  - `SchemaType` with any other key records `SchemaType: unknown dialect "postgress"; the keys are field.Postgres, field.MySQL and field.SQLite`.
- **Index `Where` doc.** "Sets the predicate of a partial index, in SQL. PostgreSQL and SQLite have partial indexes; MySQL does not."

### Task 7: Plugin protocol 2 and `plugin.Main`

**Files:**

- Create: `plugin/main.go`, `plugin/main_test.go`.
- Modify: `cmd/velox-gen/plugin.go`, `generate.go` (`headerFor`, `staleFiles`, the case fold, the rerun quoting), `main.go` (the `-plugin` flag doc), and `cmd/velox-gen/testdata/fakeplugin/main.go`.

**Interfaces:**
- `ProtocolVersion = 2`.
- `Request` gains:
  - `Generator string` (`json:"generator"`), which is `"velox-gen " + <velox2 module version>` (Task 8's `version` reads the same value; until then `"velox-gen (devel)"` is fine);
  - `Options map[string]string` (`json:"options,omitempty"`).
- `Response` gains:
  - `Protocol int` (`json:"plugin_protocol"`), which the plugin echoes;
  - `Warnings []string` (`json:"warnings,omitempty"`).
- `File.Path` is a slash path below the output directory. It is refused when it is empty, absolute, contains `\`, `..`, `.` or empty segments, or a NUL, or ends in anything but `.go`, `.graphqls` or `.proto`.
- In `plugin/main.go`:

```go
// Supports holds the versions a plugin was written for, as literals in its
// own source: plugin.Supports{Protocol: 2, Model: 2}.
type Supports struct{ Protocol, Model int }

// GenerateFunc answers one request.
type GenerateFunc func(req *Request) (files []File, warnings []string, err error)

// Run reads a request from in, checks it against s, calls gen and writes the
// response to out. It returns an error only when out cannot be written.
func Run(s Supports, in io.Reader, out io.Writer, gen GenerateFunc) error

// Main is Run on standard input and output; it exits 1 when Run fails.
func Main(s Supports, gen GenerateFunc)
```

- `Run` answers with an error response, and never calls `gen`, when:
  - `s.Protocol != ProtocolVersion`: `this plugin was written for plugin protocol 1; the velox2 it is built with speaks 2: update the plugin`;

  - the model is missing;
  - the model's version differs from `s.Model`.

  Every response carries `Protocol: ProtocolVersion`.
- **velox-gen.**

## Rulings this plan makes

Each is a call made while writing this plan. An implementer who finds one wrong stops and reports it instead of changing it.

1. **(call)** Model 2 drops `Nillable` and keeps `Optional`. Since §3.1's correction, `Optional` is no nullability flag: it says a field need not be given on create, which GraphQL's create input and gRPC's create request need. `Pointer` and `Nullable` are the nullability flags, as §3.3 says. velox-graphql reads `Nullable` where it read `Nillable`.
2. **(call)** The load model's types move to `internal/gen/loadjson`. That is under `internal/gen` as §3.5 says, and `schema/load` can still import it: `internal/gen`'s own `internal/` cannot be imported from `schema/load`. `loadjson.Version` becomes 2.
3. **(call)** Builder misuse travels in the model's `Errors`, not as `Marshal`'s error, so velox-gen prints it in the same format as rule errors, with relative positions.
4. **(call)** A builder records every misuse (`Errs []error`), not the first. §3.6 says "all builder errors are reported together".
5. **(call)** Positions are kept out of the Graph's JSON, so the model hash and every generated file stay independent of the checkout path.
6. **(call)** `DefaultFunc` and `UpdateDefault` keep taking `any`: they are ent's spellings, and a GoType changes the type they must return. The typed forms are `Number[T]`, `EnumOf[T]`, `UUIDOf[T]` and `Time.Default`/`UpdateDefault`. Old velox and ent both take `any` for `Time.Default`. §3.6 asks for it typed, and `time.Now` still compiles.
7. **(call)** A time GoType's default must convert from `time.Time`. The generated code converts it, compatibly.
8. **(call)** Contradictions inside one builder are builder errors. Contradictions across elements are numbered rules 41–47. Rules 37, 39 and 40 keep their numbers and messages in one table.
9. **(call)** A duplicate index means the same columns in order, the same `Unique` and the same `Where`, among declared indexes (mixins' included). A field's `Unique()` is not compared with them.
10. **(call)** `OnDelete` is a method on both edge builders, with three actions: `Cascade`, `SetNull` and `Restrict`. It is refused on M2M. `SetNull` needs a NULL-able key. Both sides of a pair must agree. It is recorded for the migration planner and stays out of the plugin model, since added fields need no version bump later.
11. **(call)** The dialect keys equal the core's names (`postgres`, `mysql`, `sqlite`), and an unknown key is a builder error. The review's "refuse `Where` on MySQL" waits for the migration planner.
12. **(call)** A response echoes `plugin_protocol`. That is how velox-gen tells a protocol-1 plugin apart and gives it a clear error, whatever that plugin does with the request.
13. **(call)** `plugin.Run` is exported beside `Main`, so plugins test without a subprocess. `GenerateFunc` returns files, warnings and an error. `Run` also refuses `Supports.Protocol != ProtocolVersion`, which is the check that is not vacuous.
14. **(call)** `Request.Generator` is `velox-gen <velox2 module version>`.
15. **(call)** Options are `-plugin name:key=value,key=value`. A malformed option is a usage error (exit 2).
16. **(call)** The stale-file sweep is recursive. It skips `.`- and `_`-prefixed directories, and removes only the directories it emptied.
17. **(call)** Paths fold case over the whole path, not the base name. Warnings print and never fail a run.
18. **(call)** `GeneratedCodeIsVersion` stays 4. The generated code changes only in `velox.go`'s hash and in a converted time default, and both compile against the version-4 core unchanged.
19. **(call)** Exit codes: 0 success, 1 error, 2 misuse, 3 stale. verify's stale plugin file is 3. No subcommand means `generate`.
20. **(call)** `version` prints `velox-gen <v> (generated code 4, plugin protocol 2, model 2)`.
21. **(call)** The naming golden has no `-update` flag: editing it by hand is the deliberate act a frozen table needs.
22. **(call)** Left out, as §3.3–3.6 do not ask for them:
    - "did you mean" for names;
    - `Through`, `Deprecated` and `SchemaDefault`;
    - `schema.Handles`;
    - dropping the model hash;
    - enum `String()`/`Valid()`.

    The review's Could list keeps them.
