# The API Naming Pass — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Before the names freeze at 1.0:
- every exported name has one form per kind, across every module;
- every exported identifier has Go-form godoc;
- `.golangci.yml` enforces both, generated code included, so `scripts/ci-local.sh` fails on a regression.

**Architecture:** This is a rename pass with no behaviour change. The tasks follow package boundaries.
- Task 1 renames velox's identifiers and moves every consumer in every module with them, so the tree builds. That includes velox-gen's output, velox-graphql's single `velox.SkipPolicy` emit, and the examples' calls. It bumps velox to `GeneratedCodeIsVersion5` and regenerates.
- Task 2 is migrate's renames and its godoc.
- Task 3 is contrib/graphql's renames, the `Option` struct and the bump to veloxgql `GeneratedCodeIsVersion2`, with a regeneration.
- Task 4 is the godoc everywhere else, the "For generated code." position, the method-doc test and the builtin shadows.
- Task 5 adds the linters and brings every module to zero findings.

There are no templates. velox-gen writes code from format strings in `internal/gen/render.go` and `out.go`, and velox-graphql from format strings in `contrib/graphql/internal/gogen/*.go`. So a rename of an emitted identifier is an edit to a format string, followed by the regeneration steps in R below.

**Tech Stack:** Go 1.27; golangci-lint v2.14.0 (revive, errname, staticcheck), as `scripts/ci-local.sh` pins it; gqlgen v0.17.86 in example/graphql.

**Spec:** `docs/specs/2026-10-25-naming-design.md`. Its final block, **"Rulings on the builder check"**, is binding and overrides the rulings above it where they differ. In this plan, "spec ruling N" is item N of the spec's Rulings, and "builder ruling N" is item N of that final block. Every file:line below was taken at 97e6c76.

## Global Constraints

- **No deprecated aliases.** An old name is deleted, not kept as an alias. `oldapi_test.go` (velox) and `veloxgql/api_test.go`'s `publicAPI` (veloxgql) pin this.

## Review Focus

1. **An old name survives.** It could survive as an alias, a stale doc comment's first word, an error string, a README line, or a generated file that was not regenerated. A user reading the godoc or an error would then meet a name that does not compile. Pins:
   - each task's leftover grep, which expects no output;
   - Task 1's `oldapi_test.go` additions;
   - Task 3's `publicAPI` list, which is exact.
2. **Old generated code meets the new runtime.** Code generated by the previous velox-gen must fail to compile, not misbehave. Pins:
   - Task 1's `TestOldAPIIsGone` requires `GeneratedCodeIsVersion5` to be listed and `GeneratedCodeIsVersion4` to be absent;
   - Task 3's `publicAPI` holds `GeneratedCodeIsVersion2` and not `GeneratedCodeIsVersion1`;
   - `render_test.go:659` counts the new guard once per file;
   - G passes at every task.
3. **A zero `veloxgql.Option{}`.** A caller who builds the struct literal gets velox's behaviour: `NewExtension` panics, as `velox.Open` does on a zero `velox.Option{}`. Pin: Task 3 `TestZeroOptionPanics`, which checks both.
4. **A lint config that is quietly weaker than it reads.** Three ways it could be:
   - staticcheck's SA, S and QF checks switched off by a list of only ST codes;
   - generated files skipped;
   - a nested module that does not read the root config.

   Pins, in Task 5:
   - a canary that must produce a staticcheck SA finding and a revive finding in a file marked generated;
   - `golangci-lint config path` in each module.
5. **Error text a user greps for.** `ErrNoShard`'s and `ErrNoTenant`'s messages name `WithShard` and `WithAllTenants` after the rename. `errors.Is` is unchanged. Pin: Task 1's `shard_test.go:203` table expects the new names in the text, and its `errors.Is` cases are unchanged.

## Rulings this plan makes

Each is a call made while writing this plan. An implementer who finds one wrong stops and reports it instead of changing it.

1. **(call) Task 1 moves every consumer of velox's renamed names, in every module.** That covers velox-graphql's `velox.SkipPolicy` emit, contrib's tests and docs, veloxotel's tests and the examples. A task boundary that left contrib/graphql or the examples broken would fail the gate, and the gate passes at every commit. Task 3 then changes only contrib/graphql's own names.
2. **(call) Examples are regenerated in Task 1 and again in Task 3.** Task 1 regenerates for `GeneratedCodeIsVersion5`, `EdgeDesc` and `WithoutPolicy`; Task 3 regenerates for veloxgql's names and guard. Regenerating is cheap, and each commit's G must be clean.
3. **(call) migrate's builtin shadows move into Task 2.** The task brief put every shadow in Task 4. Moving migrate's lets Task 2 end at `0 issues.` for `./migrate/...` under the final config, which is a sharper check than a residual count. Task 4 keeps the rest.
4. **(call) `comparable` becomes `parsed`.** The second result of `same` and `samePredicate` reports that both predicates parsed and so could be compared. The other shadows take the names in Task 4's Files. None of them collides with a builtin or an imported package.
5. **(call) `TestExportedMethodsHaveDocs` lives in the root's `godoc_test.go`, reads the other modules' hand-written packages by path, and leaves out `internal/`, `cmd/`, `example/`, `bench/` and generated files.** Builder ruling 7 puts it in godoc_test. Reading by path with `go/parser` needs no import of the nested modules. The packages it reads are Goal 1's public ones.
6. **(call) A doc is "marked" when, with white space collapsed, the text after its first `". "` starts with `For generated code.`** The first sentence of a marked doc avoids abbreviations with a period, such as "e.g.".
7. **(call) The zero `veloxgql.Option` panics through its nil `apply`, with no check added.** That is exactly what `velox.Open` does. `TestZeroOptionPanics` pins both, so they cannot drift apart.
8. **(call) Tasks 2 and 4 lint against an uncommitted copy of Task 5's config.** That lets each task check its own godoc with the final rules, while the committed `.golangci.yml` changes once, in Task 5, together with the last fixes. Without it the gate would fail between commits.
9. **(call) `oldapi_test.go` lists every deleted root function and type.** A go doc regexp per old name pins "no deprecated aliases" for velox, as `publicAPI` pins it for veloxgql. migrate's renamed constants are pinned by Task 2's leftover grep.
10. **(call) The followups' resolved items keep their names.** They record what was done at the time, so they are history. Open items name the new identifiers.
