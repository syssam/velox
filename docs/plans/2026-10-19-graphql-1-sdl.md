# GraphQL Plan 1: Plugins and the SDL — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `go tool velox-gen -out gen -plugin velox-graphql ./schema` writes a valid GraphQL SDL for the schema into the `gen` package. The SDL covers types, Node, connections, ordering, where inputs and mutation inputs, and is controlled by `graphql.*` annotations. `-check` and `verify` cover it.

**Architecture:**
- A new public package `plugin` holds the versioned, resolved model that velox-gen hands to plugins.
- velox-gen runs each `-plugin` as `go tool <name>`, with the model on stdin. It writes the plugin's files with its own ownership rules.
- The `contrib/graphql` module holds:
  - the annotations (package `graphql`, which imports only `velox2/schema`);
  - the plugin (`cmd/velox-graphql`), which renders the SDL from the model and checks it with gqlparser.
- No Go bindings are generated in this plan. Plans 2–4 add them.

**Tech Stack:** Go 1.27; `github.com/vektah/gqlparser/v2` in `contrib/graphql` only.

**Spec:** `docs/specs/2026-10-19-graphql-design.md` (§1 Plugins, §2 Annotations, §3 The generated surface). The schema design `docs/specs/2026-10-15-schema-design.md` is context.

## Global Constraints

- **Core rules.**
  - Go 1.27 generic methods: every method of a generic velox type is generic.
  - Nothing runs at program start.
  - No reflect in generic code.
  - Core's allocation budgets (`go test -run Budget -v .`) and the escape check are unchanged. The escape check is `go build -gcflags=-m . 2>&1 | grep "db.go:$(grep -n 'func (db \*DB) plain' db.go | cut -d: -f1):"` and must print `leaking param content: st` and `read does not escape`.
- **No GraphQL dependency outside `contrib/graphql`.**
  - The root module, `cmd/velox-gen` and the `plugin` package gain no dependency on gqlgen or gqlparser.
  - `go list -deps ./...` in the root and in `cmd/velox-gen` shows neither.
- **The annotations package `github.com/syssam/velox2/contrib/graphql` imports only the standard library and `github.com/syssam/velox2/schema`.** A test pins this.
- **Generated files.**
  - Every file velox-gen writes, including a plugin's, starts with the header line for its kind:
    - `.go`: `// Code generated by velox-gen. DO NOT EDIT.`
    - `.graphqls`: `# Code generated by velox-gen. DO NOT EDIT.`
  - velox-gen adds the header; a plugin's content does not include it.
  - velox-gen writes, checks, and removes as stale only files that start with their header.
- **The plugin protocol.**
  - The request is JSON `{"plugin_protocol": 1, "out_package": "<name>", "out_path": "<import path>", "model": <plugin.Model>}` on stdin.
  - The response is JSON `{"files": [{"path": "<rel>", "content": "<text>"}], "error": "<text>"}` on stdout.
  - Paths are relative to `-out`, with no directory part in v1, and end in `.go` or `.graphqls`.
  - A non-empty `error`, a non-zero exit or an invalid path fails the run, and nothing is written.
- **Plugin names.** `-plugin` takes a tool name that `go tool` resolves in the application's module, such as `velox-graphql`.
- **CI.**
  - `scripts/ci-local.sh` and `.github/workflows/ci.yml` match line for line.
  - The new module `contrib/graphql` gets vet, golangci-lint v2.14.0 and race tests in both.
- **No machine-specific paths** in committed files. Set a scratch `GOCACHE` and `GOFLAGS=-p=2` only in the shell.
- **Commits** end with a blank line and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push.

## Rulings this plan makes on the spec

1. **The SDL file is `gen/velox.graphqls`,** in the package directory, flat. velox-gen's stale-file scan reads only that directory. The spec is updated to say so.
2. **velox-gen adds the header to a plugin's files,** so a plugin cannot forget it and ownership stays velox-gen's rule.
3. **`plugin.Model` is built from `gen.Graph` and `gen.Out`.** It carries what both hold:
   - entity, field and edge names and Go names;
   - columns;
   - Go types and handles;
   - relation kinds and join entities;
   - the tenant column;
   - immutable, optional, sensitive and default flags;
   - enums;
   - raw annotations.

   Its JSON is versioned (`plugin.ModelVersion = 1`; the protocol has its own, `plugin.ProtocolVersion = 1`). A test pins its JSON for the blog test model, as a golden file.
4. **The annotation is one struct, `graphql.Annotation`,** named `"graphql"`, implementing `schema.Merger`. The constructors return it, so one `Annotations()` list may hold several, and they merge.

## Review Focus

1. **A plugin that writes outside `-out` or overwrites a user's file.** A path with `/`, `..` or another extension, or a file present without the header, fails with nothing written. Task 2's `TestPluginPathsAreChecked` pins this.
2. **`-check` and stale-file removal for `.graphqls`.** A changed schema makes `-check` fail and names `velox.graphqls`. Removing the plugin from the command removes the plugin's files on the next generate. Task 2's `TestPluginFilesAreOwned` pins this.
3. **An SDL that gqlgen will not load.** Every golden SDL is parsed and validated by gqlparser against the scalars and directives it declares. Task 4's `TestSDLIsValid` pins this.
4. **A name collision in the SDL.** Two entities whose enum types, inputs or connections would share a name fail generation with both names. Task 5's `TestNameCollisions` pins this.
5. **An annotation on the wrong kind of element** (`OrderField` on an edge, `Mutations` on a field) or `OrderField` on an optional field. The plugin fails with the schema and field named. Task 5's `TestAnnotationMisuse` pins this.

**Interfaces:**
- Produces, in package `plugin`:
  ```go
  const ProtocolVersion = 1 // Request.Protocol
  const ModelVersion = 1    // Model.Version
  type Request struct {
      Protocol   int    `json:"plugin_protocol"`
      OutPackage string `json:"out_package"`
      OutPath    string `json:"out_path"` // the generated package's import path
      Model      *Model `json:"model"`
  }
  type Response struct {
      Files []File `json:"files"`
      Error string `json:"error,omitempty"`
  }
  type File struct{ Path, Content string } // json "path", "content"
  type Model struct {
      Version    int
      SchemaPath string
      Entities   []*Entity
      Enums      []*Enum
  } // the Graph's entities, then join entities, each sorted by Name
  type Entity struct {
      Name, Label, Handles, Table string
      Join                        bool
      Fields                      []*Field
      Edges                       []*Edge
      PrimaryKey                  []int
      Tenant                      int // -1 none
      Annotations                 map[string]json.RawMessage
  }
  type Field struct {
      Name, GoName, Column, Type, GoType, ElemType string
      Pointer, Optional, Nillable, Immutable, Sensitive, Unique, AutoID bool
      HasDefault, UpdateDefault                                         bool
      Implicit                                                          string // the edge whose foreign key it is
      Enum                                                              string // the enum type name, "" when not an enum
      Annotations                                                       map[string]json.RawMessage
  }
  type Edge struct {
      Name, GoName, Target, Ref string
      Kind                      string // "O2O", "O2M", "M2O" or "M2M", exactly gen.Rel.Kind
      Unique, Required, Inverse, Immutable bool
      Field                     string // the foreign-key field's Name, on whichever entity holds it; "" for M2M
      Join                      string // the join entity's Name for M2M, else ""
      Annotations               map[string]json.RawMessage
  }
  type Enum struct {
      Type   string
      Values []string // stored values, in declaration order
  }
  ```
  - Use snake_case JSON tags throughout.
  - `Field.Type` is the schema field type (`load.Field.Type`). `GoType`/`ElemType` are as in `gen.OutField`.

**Interfaces:**
- Produces, in package `graphql`. This is the JSON the plugin reads; the plugin decodes `Annotation` from the model's `"graphql"` key.
  ```go
  type Annotation struct {
      Skip          SkipMode          `json:"skip,omitempty"`
      Type          string            `json:"type,omitempty"`
      QueryField    string            `json:"query_field,omitempty"`
      Mutations     []MutationKind    `json:"mutations,omitempty"` // "create", "update", "delete"
      MultiOrder    bool              `json:"multi_order,omitempty"`
      FieldName     string            `json:"field_name,omitempty"`
      OrderField    string            `json:"order_field,omitempty"`
      WhereOps      WhereOp           `json:"where_ops,omitempty"`
      WhereEdge     bool              `json:"where_edge,omitempty"`
      Connection    *bool             `json:"connection,omitempty"`
      CreateInput   *bool             `json:"create_input,omitempty"`
      UpdateInput   *bool             `json:"update_input,omitempty"`
      EnumValues    map[string]string `json:"enum_values,omitempty"`
      Directives    []Directive       `json:"directives,omitempty"`
  }
  func (Annotation) Name() string // "graphql"
  func (a Annotation) Merge(other schema.Annotation) schema.Annotation
  type SkipMode uint16 // SkipType, SkipEnumField, SkipOrderField, SkipWhereInput, SkipMutationCreateInput, SkipMutationUpdateInput, SkipAll
  type WhereOp uint32 // OpEQ, OpNEQ, OpIn, OpNotIn, OpGT, OpGTE, OpLT, OpLTE, OpContains, OpHasPrefix, OpHasSuffix, OpIsNil, OpNotNil; presets OpsEquality, OpsComparison, OpsString, OpsNullable, OpsAll
  type MutationKind string
  type Directive struct {
      Name string
      Args map[string]any
  }
  func Skip(modes ...SkipMode) Annotation // no args: SkipAll
  func Type(name string) Annotation
  func QueryField(name string) Annotation
  func Mutations(kinds ...MutationKind) Annotation // no args: create and update
  func Create() MutationKind
  func Update() MutationKind
  func Delete() MutationKind
  func MultiOrder() Annotation
  func FieldName(name string) Annotation
  func OrderField(name string) Annotation
  func WhereOps(ops ...WhereOp) Annotation // no args: the defaults by field type (spec §3 Filtering)
  func WhereEdge() Annotation
  func Connection(on bool) Annotation
  func CreateInput(on bool) Annotation
  func UpdateInput(on bool) Annotation
  func EnumValues(m map[string]string) Annotation
  func Directives(ds ...Directive) Annotation
  ```
  - `WhereOps()` with no arguments records a sentinel `OpsDefault`, which the plugin resolves by field type.
  - `Merge` combines field by field: bitmasks OR, lists append, non-zero scalars from the later annotation win.

### Task 5: Ordering, where inputs and mutation inputs in the SDL

**Files:**
- Modify: `contrib/graphql/internal/sdl/render.go`, with new files `order.go`, `where.go` and `input.go` beside it.
- Modify: the Task 4 golden testdata.
- Test: `contrib/graphql/internal/sdl/{order,where,input,rules}_test.go`.

**Interfaces:**
- Consumes: Task 4's `Render`.
- Produces:
  - **Ordering:**
    - `input XOrder { direction: OrderDirection! = ASC, field: XOrderField! }`;
    - `enum XOrderField`, the `OrderField` names;
    - `orderBy: XOrder`, or `[XOrder!]` with `MultiOrder`.
  - **Filtering:**
    - `input XWhereInput { not: XWhereInput, and: [XWhereInput!], or: [XWhereInput!], <field><Op>…, has<Edge>: Boolean, has<Edge>With: [YWhereInput!] }`;
    - predicate names as entgql writes them: `name`, `nameNEQ`, `nameIn`, `nameNotIn`, `nameGT`, `nameGTE`, `nameLT`, `nameLTE`, `nameContains`, `nameHasPrefix`, `nameHasSuffix`, `nameIsNil`, `nameNotNil`;
    - an ID-typed predicate takes `ID`;
    - a foreign key appears as `<edge>ID`/`<edge>IDIn`/`<edge>IDNotIn` with `ID`.
  - **Mutation inputs** (spec §3 Mutations):
    - `input CreateXInput` and `input UpdateXInput`;
    - `createX(input: CreateXInput!): X!`, `updateX(id: ID!, input: UpdateXInput!): X!` and `deleteX(id: ID!): ID!` in `type Mutation`, only for the kinds `Mutations` lists;
    - no `Mutation` type when no entity has mutations.
  - **Input rules:**
    - immutable fields are left out of `UpdateXInput`;
    - fields with a default (Default or DefaultFunc) are optional in `CreateXInput`;
    - a field with `UpdateDefault` and no create-time default is left out of `UpdateXInput` (the `UpdateDefault` fills it). In `CreateXInput` it is required when it is not nullable, because nothing fills it on insert, and left out when it is nullable;
    - `CreateInput(false)`/`UpdateInput(false)` leave a field out;
    - the tenant column and implicit foreign keys are never inputs; their edges stand for them;
    - an update input with no fields gets no type, and its `updateX` is not written.
