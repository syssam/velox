# API Plan 1: Core Cleanup — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the core's breaking API changes before 1.0:
- `Tx` passes its context;
- a policy states "no restriction" explicitly;
- a dry run sends no write;
- clearer names;
- `Save` becomes a builder;
- raw SQL with a reason;
- one nullability rule;
- velox-gen joins the root module;
- the generated-code contract is written down, at version 4.

**Architecture:** Each task changes one rule of the public API and updates every caller in the same commit: core, generated code, examples, contrib, itests and docs. The repository builds and passes after every task. Generated code moves to `GeneratedCodeIsVersion4` in Task 5. Every golden and example is regenerated whenever its output changes.

**Tech Stack:** Go 1.27; no new dependency.

**Spec:** `docs/specs/2026-10-20-api-cleanup-design.md`, §1, §2.1–2.2, §3.1, §3.2 and §7. The reviews behind it are in `docs/reviews/2026-10-20-api-review-*.md`.

## Global Constraints

- **Core rules.**
  - Go 1.27 generic methods: every method of a generic velox type is generic `[_ Lazy[…]]` (`methods_test.go`).
  - Nothing runs at program start.
  - No reflect in generic code.
- **Budgets and escape check.**
  - `go test -run Budget -v .` must stay at: one-row 6, tenant 7, hundred rows 105, tx 9/6, observed 7/6, metadata 19, Insert 13, replica one-row 6.
  - A task that changes a number must say why and get a controller ruling.
  - The escape check is unchanged. `go build -gcflags=-m . 2>&1 | grep "db.go:$(grep -n 'func (db \*DB) plain' db.go | cut -d: -f1):"` prints `leaking param content: st` and `read does not escape`.
- **Every caller moves with the API.**
  - Callers are: core tests, `internal/itest`, `internal/testmodel`, `bench/scale`, `example/*`, `contrib/otel`, `contrib/graphql` (including its generated code and goldens), and every doc snippet.
  - No deprecated aliases are left behind. velox2 has no users yet, and an alias is a second way to do the same thing.
- **The full gate passes at every task's commit:** `<scratchpad>/fix1.sh`, with Docker.
- **CI.** `scripts/ci-local.sh` and `.github/workflows/ci.yml` stay identical.
- **No machine-specific paths** in committed files. Set `GOCACHE=<scratchpad>/velox2-gocache` and `GOFLAGS=-p=2` in the shell only.
- **Commits** end with a blank line and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push.

## Review Focus

1. **`ErrOutsideTx` false positives.** These must not fail:
   - a statement on the transaction's `*DB` with a context derived from the transaction's ctx;
   - a savepoint;
   - the `TxAround` hooks' own work;
   - a goroutine started inside the transaction with the outer context.

   A statement on the outer `db` with the transaction's ctx must fail. Task 2's table test pins this.
2. **A dry run reaching a write through a hook.** `db.Insert(&x).SQL(ctx)`, with an insert hook that writes an audit row through `m.DB()`, returns the SQL and writes nothing. Reads inside the hook still run. Task 4 pins this.
3. **A policy written the old way.** A `Read` that returns a zero `Pred` for some roles fails for those roles with an error naming the entity. It never lets them through. Task 3 pins this.
4. **`Raw` reaching tenant data.** `db.Raw` with an empty reason fails. With a reason, it runs, and `Statement.TenantBypass` shows the reason to Around hooks, and so to contrib/otel. Task 7 pins this.
5. **The nullability change rewriting user structs.** Each example and the testmodel regenerate cleanly. A required bool or number field with a `Default` fails generation with the message the spec gives. Task 8 pins this.

### Task 2: `Tx` passes its context; `ErrOutsideTx`

**Files:** `tx.go`, `errors.go`, `db.go` (the check), `txhook.go`, and every caller.

**Interfaces:**
- `func (db *DB) Tx(ctx context.Context, fn func(ctx context.Context, tx *DB) error, opts ...TxOption) error`.
- `var ErrOutsideTx = errors.New("statement outside its transaction")`.
- The ctx passed to `fn` carries an unexported mark with the transaction's identity. A statement on a `*DB` that is not that transaction, or a savepoint of it, under a ctx with the mark, fails with `velox: <Entity>: statement outside its transaction`.
- The check is one context lookup, and it runs only when the statement's `*DB` is not in a transaction. Hold the tx budget 9/6 and the one-row budget 6. If the lookup costs an allocation on the non-tx path, report it instead of absorbing it.

- [ ] **Step 1:** Write the failing tests.
  - `TestTxPassesItsContext`: the ctx `fn` gets has the transaction's deadline, and it has the values a `TxAround` hook added.
  - `TestStatementOutsideItsTx`, a table over Review Focus 1's cases.
- [ ] **Step 2:** Run them. Expected: FAIL (signature).
- [ ] **Step 3:** Implement the change and update every caller.
- [ ] **Step 4:** Run the budgets, the escape check and the full gate. Expected: unchanged, rc=0.
- [ ] **Step 5:** Commit `Tx passes its context; a statement outside its transaction fails`.

### Task 3: `Allow[E]` and the zero policy predicate

**Files:** `scope_api.go`, `scope.go`, `errors.go`, and every caller (examples' `Policy()` files, tests).

**Interfaces:**
- `func Allow[E any]() Pred[E]`, a predicate that matches every row and renders to nothing.
- A zero `Pred` returned by `Policy.Read` or `Policy.Write` fails the statement with `velox: <Entity>: policy returned no predicate; return velox.Allow[E]() for no restriction`.
- `Allow` composes: `Or(Allow(), x)` is Allow, and `And(Allow(), x)` is x.

- [ ] **Step 1:** Write the failing tests.
  - `TestPolicyZeroPredFails` (Review Focus 3).
  - `TestAllowComposes`.
  - `TestAllowRendersNothing`: the SQL is identical to having no policy.
- [ ] **Step 2:** Implement the change, update the examples' policies, and run the full gate. Expected: rc=0.
- [ ] **Step 3:** Commit `A policy says Allow for no restriction`.

### Task 4: A dry run sends no write

**Files:** `db.go`, `tx.go`, `write.go`, `insert.go`, `errors.go`, `scope_api.go`.

**Interfaces:**
- `var ErrDryRun = errors.New("write in a dry run")`.
- Under a ctx that `IsDryRun` reports true:
  - `Exec` on Insert, InsertAll, Update and Delete, `Save`, `Raw`/`Exec` (Task 7) and `Tx` fail with `ErrDryRun` before sending;
  - reads run as normal;
  - the statement being dry-run itself is rendered, not sent, as today.
- `InsertQuery.SQL`'s doc says it fills defaults into the caller's structs.

- [ ] **Step 1:** Write the failing tests: `TestDryRunSendsNoWrite` (Review Focus 2, with a hook writing through `m.DB()`), and `TestDryRunReadsRun`.
- [ ] **Step 2:** Implement the change. Update `example/hooks`, whose audit hook checks `IsDryRun` by hand; it no longer needs to. Run the full gate. Expected: rc=0.
- [ ] **Step 3:** Commit `A dry run sends no write`.

**Files:** `errors.go`, `tx.go`, `route.go`, `doc.go`, every godoc that cites a spec section, `internal/gen` (the version), every generated file and golden, `contrib/graphql` (it references `GeneratedCodeIsVersion3` in goldens and tests), and the docs.

**Interfaces:**
- **Renames:**

  - `TxTimeout`, `TxReadOnly`, `TxIsolation` and `TxRetrySerializable` replace `Timeout`, `ReadOnly`, `Isolation` and `RetrySerializable`.
  - `ReadPrimary` replaces `Primary`.
- **Version:** `GeneratedCodeIsVersion4` replaces `GeneratedCodeIsVersion3`, and velox-gen writes the new name.
- **Package doc:** a "Generated code" section. Each of those types' docs opens with "For generated code."
- **godoc:**
  - No doc cites "design §…", "Ruling N" or "spec".
  - Options and context decorators are grouped by the doc's headings.
  - `DB` says it is safe for concurrent use.
  - `Tx` says a panic re-panics.
  - Sentinel docs follow "ErrX is returned by … when …".

- [ ] **Step 1:** Make the renames and the version bump, regenerate everything, and update the callers and docs.

### Task 6: `Save` is a builder

**Files:** `write.go`, and every caller.

**Interfaces:**
- `func (db *DB) Save[E any, PE Entity[E]](x PE, col Column[E], more ...Column[E]) SaveQuery[E]`.
- `func (s SaveQuery[E]) Where[_ Lazy[E]](ps ...Pred[E]) SaveQuery[E]`: extra conditions, ANDed with the key.
- `func (s SaveQuery[E]) Exec[_ Lazy[E]](ctx context.Context) error`: the semantics of today's `Save`, including `ErrNotFound` when no row matches the key and conditions.
- `func (s SaveQuery[E]) SQL[_ Lazy[E]](ctx context.Context) (string, []any, error)`.

- [ ] **Step 1:** Write the failing tests.
  - `TestSaveBuilder`: optimistic locking with a stale version gives `ErrNotFound`, and the row is unchanged.
  - `TestSaveSQL`.
  - A compile-time check that `db.Save(&x)` with no column does not compile, in a `go vet`-free test file built by `go/types`, or documented if impractical.
- [ ] **Step 2:** Implement the change, update the callers, and hold the budgets. Run the full gate. Expected: rc=0.
- [ ] **Step 3:** Commit `Save is a builder`.

### Task 7: Raw SQL with a reason

**Files:** create `raw.go`; modify `statement.go` (`OpRaw`), `db.go` (the path), `scope.go` (no scope for raw), contrib/otel if it switches on `Op`.

**Interfaces:**
- `func (db *DB) Exec(ctx context.Context, reason, query string, args ...any) (int64, error)`.
- `func (db *DB) Raw[E any, PE Entity[E]](reason, query string, args ...any) RawQuery[E]`, with `All`, `One` and `Iter` scanned by column name into E's fields, with codecs applied. Unknown columns are an error; missing columns stay zero.
- `OpRaw` statements:
  - go through the Around hooks, deadlines, routing (a write goes to the primary; `ReadPrimary` is honoured), the dry-run rule and the row cap;
  - skip scope and policy, with `Statement.TenantBypass = reason`;
  - an empty reason fails before anything runs.
- The doc says raw SQL is the escape hatch for locking, CTEs and anything the builder cannot express, and that tenant scoping is the caller's.

- [ ] **Step 1:** Write the failing tests.
  - `TestRawNeedsAReason`.
  - `TestRawScansByName`.
  - `TestRawRoutes`: a write goes to the primary.
  - `TestRawShowsReason` (Review Focus 4).
  - `TestRawUnknownColumn`.
  - An itest on all four drivers.
- [ ] **Step 2:** Implement the change, add one `Raw` use to `example/tour` (a `FOR UPDATE` inside a `Tx` on SQLite where supported, else an aggregate), and run the full gate. Expected: rc=0.
- [ ] **Step 3:** Commit `Raw SQL, with a reason`.

### Task 8: One nullability rule

**Files:**
- `schema/field` (the `Nillable` rule);
- `internal/gen/build.go` and `lower.go` (Pointer only from Optional; refuse a `Default` on a required bool or number);
- the `plugin` model (`Optional` and `Nillable` stay as the schema said, `Pointer` follows the new rule, `Nullable` = Optional);
- contrib/graphql's SDL and Go generator;
- every example and testmodel schema that relied on the old rule;
- goldens.

**Interfaces:** spec §3.1, exactly.
- velox-gen's error for a required bool or number field with a `Default` reads: `schema X: field "f": a Default on a required bool or number cannot be told from unset; make the field Optional or drop the Default`.
- `Nillable()` without `Optional()` gives: `schema X: field "f": Nillable needs Optional`.

- [ ] **Step 1:** Write the failing tests: rules tests for both errors, a golden where `Optional()` alone gives a pointer, and a lowering test that `Default` never changes the Go type.
- [ ] **Step 2:** Implement the change. Change the examples' schemas where needed, keeping each example's teaching intent and saying what changed in each README. Regenerate. Run the full gate. Expected: rc=0.
- [ ] **Step 3:** Commit `One nullability rule: Optional makes a pointer`.
