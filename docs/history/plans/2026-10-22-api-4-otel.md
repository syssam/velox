# API Plan 4: OpenTelemetry — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the OpenTelemetry adapter ready for 1.0:
- the module path `contrib/veloxotel`, matching the package name;
- one way to configure it, `veloxotel.Options(cfg)` with `Config.Callers`, and Config booleans in one style;
- an instrumentation scope with a version and the semconv schema URL, with every name checked against the pinned semconv release;
- a `db.client.operation.duration` that leaves out `Iter`'s loop body;
- `db.namespace`, `server.address`, `server.port` and `db.response.status_code`, with the driver's code exposed by the core.

**Architecture:** The adapter stays one package of hooks over the core's `Statement` and `TxInfo`. It keeps its API-only dependency. Every semconv name stays a constant in `attrs.go`. A test-only import of the pinned `semconv` package checks each constant, so the names are checked by the compiler, not from memory. The core gains two additive things: `velox.DriverCode(err)`, which §5.4 asks for, and `Result.LoopBody`, without which no hook can tell `Iter`'s loop body from the database's time (ruling 1). Each task moves every caller in its own commit: the module, `example/otel`, CI, the local mirror and the docs. The repository passes the full gate after every task.

**Tech Stack:** Go 1.27. OpenTelemetry Go API v1.47.0 (`otel`, `attribute`, `codes`, `metric`, `trace`), unchanged. Semantic conventions **v1.43.0**: the newest `semconv` package in `go.opentelemetry.io/otel@v1.47.0`, schema URL `https://opentelemetry.io/schemas/1.43.0`. The SDK, pgx and `semconv/v1.43.0` appear in test files only. No new module dependency.

**Spec:** `docs/history/specs/2026-10-20-api-cleanup-design.md` §5, read with §6a–6d (raw SQL as `OpRawQuery`/`OpRawExec`, `Statement.TenantBypass` and `PolicyBypass`, and the core's additions so far). The evidence:

- `docs/history/specs/2026-10-15-observability-design.md` §2, with its dated notes;
- the items of `docs/history/plans/2026-10-14-core-1-followups.md` that name otel or "API plan 4";
- semantic conventions v1.43.0: `docs/db/database-spans.md`, `database-metrics.md`, `postgresql.md`, `mysql.md` and `sql.md` of `open-telemetry/semantic-conventions` at tag `v1.43.0`.

## Review Focus

1. **An `Iter` loop that breaks, or a loop body slower than the query.** The duration point must be the database's time: not negative, and without the body's time, also when the loop breaks after the first row. A loop that panics records no point, as today. Task 4 pins this with a 3-row loop whose body sleeps.
2. **A driver error under velox's wrapping.** A unique violation reaches the adapter as a `*velox.ConstraintError`, a commit error as `velox: commit: %w`, and a hook may `errors.Join` it with its own. `DriverCode` must find the code in each, and find none in a look-alike type from another package. Task 5 pins this.
3. **A read that fell over to the primary.** With `TargetFor`, the span and the duration point name the primary's server once the replica failed, not the replica's. Task 5 pins this.
4. **`CallersOff` with `App` set.** The SQL comment must carry no `caller=` key, the spans no `code.*`, and pgx must prepare one statement for two call sites of one shape. Task 2 pins this on the fake driver, and on PostgreSQL under `VELOX_TEST_POSTGRES`.
5. **A build where the module is replaced by a directory.** The scope version must then be empty, not the placeholder `v0.0.0-00010101000000-000000000000` nor `(devel)`. Task 3 pins this with a table over `debug.BuildInfo` values.

// Callers says whether statements record their call site.
type Callers uint8

const (
	// CallersOn turns on velox.WithCallers: spans carry code.* attributes,
	// and with App the SQL comment carries the call site. The default.
	CallersOn Callers = iota
	// CallersOff leaves velox.WithCallers out: no code.* attributes, and
	// one SQL comment, so one prepared statement, per shape.
	CallersOff
)

type Config struct {
	TracerProvider trace.TracerProvider // nil: otel.GetTracerProvider()
	MeterProvider  metric.MeterProvider // nil: otel.GetMeterProvider()
	App            string               // names the application in the SQL comment; empty: no comment
	CommentTags    []string             // the velox.WithTags keys the comment carries, in this order
	Callers        Callers              // CallersOn by default

	OmitQueryText           bool // leave db.query.text off spans
	RecordTenant            bool // add velox.tenant to spans
	RecordMetricFingerprint bool // add velox.fingerprint to the statement metrics
}

// Options returns the velox options that trace and measure every statement
// and transaction: velox.WithCallers unless Callers is CallersOff,
// velox.WithAround, velox.WithTxAround, and velox.WithSQLComment when App
// is set.
func Options(cfg Config) []velox.Option

- In the core:

```go
// DriverCode returns the database's code for err, as text, when err or an
// error it wraps came from the database: PostgreSQL's SQLSTATE ("23505"),
// MySQL's error number ("1062"), or SQLite's extended result code
// ("2067"). It looks through wrapping and errors.Join, as errors.As does.
func DriverCode(err error) (string, bool)
```

  It reuses `errclass.go`'s readers (`*pgconn.PgError`, `mysqlError`, `sqliteError`). It allocates only for the MySQL and SQLite numbers (`strconv.Itoa`).
- In the adapter:

```go
// Target names the database server a statement ran on. A zero field
// leaves its attribute off.
type Target struct {
	Namespace string // db.namespace: PostgreSQL "{database}|{schema}", MySQL the database
	Address   string // server.address: the host name, IP address or socket
	Port      int    // server.port, set only with Address
}

type Config struct {
	// …
	Target    Target                      // every statement's server
	TargetFor func(r velox.Route) Target  // per shard and replica; when set, used instead of Target
}
```

- **When the attributes are set:**
  - Without `TargetFor`, `Target`'s attributes are built once in `newAdapter` and appended to each span's start attributes and each metric point.
  - With `TargetFor`, it is called with `st.Route` when the span starts (the route stage ran before the Around hooks). It is called again after `next` only when `st.Route` changed (a fallback); the span's attributes are then set again and the metric point uses the new ones.
  - The transaction span gets none: it is not a database client span.
- **`db.response.status_code`** is set, on a failed statement only, on the span and on the duration point, from `velox.DriverCode(err)`.
- **`error.type`** keeps velox's values. Where it would be `_OTHER` and the error has a driver code, it is the code (`40001` for a serialization failure). The transaction's retry events use the same rule.
- New constants `attrDBNamespace = "db.namespace"`, `attrServerAddress = "server.address"`, `attrServerPort = "server.port"`, `attrStatusCode = "db.response.status_code"`.

## Rulings this plan makes

Each is a call made while writing this plan. An implementer who finds one wrong stops and reports it instead of changing it.

1. **(call)** The core gains `Result.LoopBody` as well as `DriverCode`. The brief limits the core to what §5.4 needs, but §5.3 cannot be met without it: the loop body runs inside `next`, and no hook sees a row being yielded. The review's other option, a `velox.iter` metric attribute, needs a core field too. `LoopBody` is additive, measured only when an Around hook exists, and allocates nothing; Task 4 checks the budgets.
2. **(call)** The pinned release is semconv v1.43.0, the newest that `go.opentelemetry.io/otel@v1.47.0` carries. The adapter still writes its names out (observability §2.4). A test-only import of `semconv/v1.43.0` and `dbconv` checks every one, so a later bump is a compile-checked change.
3. **(call)** `Config.Callers` is a type, `Callers`, with `CallersOn` as its zero value, not a bool. `Options` turned call sites on until now, and a bool named `Callers` would have to default to off. A type also leaves room for a later mode, such as call sites on spans but not in the comment.
4. **(call)** The booleans are `OmitQueryText`, `RecordTenant`, `RecordMetricFingerprint` and `RecordReturnedRows`: a verb, then what it acts on. `Omit` turns off a default; `Record` turns on an extra. Only `MetricFingerprint` is renamed.
5. **(call)** `Around` and `TxAround` are removed outright. An application that wants `WithCallerSkip` passes it after `Options`. The tests get the hooks through `export_test.go`.
6. **(call)** The scope's version is read from `debug.ReadBuildInfo`, since velox tags no releases and a constant would go stale. `(devel)` and a module replaced by a directory give no version, rather than a placeholder.
7. **(call)** `db.namespace` and the server come from `Config.Target`, or per route from `Config.TargetFor`, because the adapter sees no connection string and may not import a driver. The application writes the namespace in its system's form (PostgreSQL's `{database}|{schema}`). `server.port` is set whenever it is given with an address: the conventions require it only off the default port, and allow it on the default.
8. **(call)** `TargetFor` runs at span start, so samplers see the server (the conventions ask for it at creation), and again after `next` only when the route changed. A fallback then names the primary.
9. **(call)** `velox.DriverCode(err) (string, bool)` is a function, not a field on `ConstraintError`: serialization failures, deadlocks and timeouts carry codes too and are no constraint error. The codes follow the conventions: SQLSTATE for PostgreSQL, the error number for MySQL ("not SQLSTATE"), and SQLite's extended result code, its most specific.
10. **(call)** `error.type` keeps velox's own values (`velox.denied`, `constraint.unique`…), which the conventions allow as an instrumentation's own. Where it would be `_OTHER`, it becomes the driver's code, as the conventions prefer. That closes the follow-up on `_OTHER` for retried serialization failures. SQLSTATE codes and error numbers are a bounded set, so metrics stay bounded.
11. **(call)** v1.43.0 is applied where the adapter differs from it, not only where §5 names it: `db.query.summary` is added; `db.response.returned_rows` on spans becomes opt-in (`RecordReturnedRows`); the rows histogram uses the advised boundaries; the returned-rows description is `dbconv`'s. The brief asks for the current conventions to hold.
12. **(call)** Raw SQL's `db.query.text` is recorded only when it has arguments. The conventions say non-parameterized text SHOULD NOT be collected by default, and velox cannot see literals in raw text. Its span keeps `velox.tenant_bypass` and `velox.policy_bypass`, and gets the target and the status code like any statement.
13. **(call)** The span keeps covering `Iter`'s loop body; only the metric leaves it out. The span shows how long the connection was held, and the spec asks only for the metric.
14. **(call)** The transaction span gets no namespace or server. It is velox's own internal span, and `TxInfo` has no route (a known follow-up).
15. **(call)** The gate runs the adapter's PostgreSQL tests (`-run Pg`) once Docker is up. Until now they ran only in `ci-local.sh`, and this plan adds two.
16. **(call)** Left out:
    - `Op.Raw()` and `Op.Reads()`, which the follow-ups assign to API plan 4. The brief keeps the core to what this plan needs, so they move to API plan 5;
    - the review's `Config.Filter` and `Config.Attributes` (finding 16, a Could);
    - `network.peer.address` (Recommended "if applicable"): the adapter does not see the peer;
    - a nested test module for the SDK and pgx (finding 18, a Could);
    - skipping the attribute set under a no-op MeterProvider (a follow-up perf nit).
