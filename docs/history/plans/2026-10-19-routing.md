# Routing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fill the pipeline's route stage: primary/replica splitting, read-your-writes by session pinning, replica failover, and sharding by context, with nothing changed for a DB that configures none of it.

**Architecture:** A `*DB` gains an optional router (nil when nothing is configured: one branch). The route stage runs after rendering and before the Around hooks. It picks a connection for the statement and records the choice in `Statement.Route`. Execution then uses that connection instead of `db.ex`. Shards are routers keyed by name. A transaction pins its shard and connection at begin. Routing state carried by a context (session, `Primary`, `OnShard`) shares one context key, so a routed read costs at most one more lookup.

**Tech Stack:** Go 1.27 (generic methods), the core module only (database/sql, pgx v5, modernc sqlite, go-sql-driver/mysql; no new dependency), contrib/otel.

**Spec:** `docs/history/specs/2026-10-15-routing-design.md`. Core design §5 (pipeline) and §8 (budgets), the observability design §2, and the policy design (tenants) are context.

  - `TestGenericTypesCompileSmall` passes with its rows unchanged.
- **Fail closed** (criteria 2 and 4): a statement whose shard cannot be determined is refused, and nothing is sent. No statement reaches another shard's connection.

## Rulings this plan makes on the spec

(Ruling 4 revised during Task 3 review; see the ledger.)

1. **`PgxConn` lives in the core beside `OpenPgx`.** The roadmap's dialect/pgx split moves both together. `Conn` is an opaque struct with unexported fields, so the split can later add a constructor for executors from another module without changing any routing API.
2. **One context key for the route marks.** `WithSession`, `Primary` and `OnShard` each copy the context's existing route state, change it, and store it under one key.
   - So a read on a DB with replicas makes one `ctx.Value` lookup for all three marks (spec §8).
   - The tenant lookup for `WithShardFor` is a second lookup, made only on a sharded DB.
3. **A query's `With` loads run on the connection the query ran on.** That is the replica it read, or the primary after a fallback.
   - Without this, parent rows from one replica and children from another, with different lag, could disagree: a parent with no visible children.
   - The spec's "a `With` load goes to a replica" holds: it goes to the parent's replica.
4. **Failover covers connection errors before any row reaches the caller.** On a replica, a connection-class error is retried once on the primary, whether the query call or the rows report it (`rows.Err()`, an error at Close).
   - The one exception is a reader that has already handed a row to the caller: once `Iter` has yielded a row, the error is returned and nothing is retried.
   - Readers already start again when an Around hook calls `next` again, so the retry reruns `read` on the primary's rows. It needs no rows wrapper and no allocation.
   - The classes:
     - `driver.ErrBadConn`, `sql.ErrConnDone`, `net.ErrClosed`, `io.EOF`, `io.ErrUnexpectedEOF`;
     - `pgconn.ErrConnClosed`, `pgconn.SafeToRetry`, any `*pgconn.ConnectError` (whatever the server said while connecting);
     - a `*pgconn.PgError` with code 57P01, 57P02 or 57P03;
     - go-sql-driver/mysql's `ErrInvalidConn`, recognized by type and text;
     - a `net.Error`. One that is a timeout falls over only when it comes from a dial (a `*net.OpError` with `Op == "dial"`).
   - A connection-class error always puts the replica in back-off, including when the reader has handed a row.
5. **A context that is cancelled or past its deadline never puts a replica in back-off,** and is never retried. Check `ctx.Err()` before classifying the error.
6. **After a fallback,** `Route.Replica` is `-1` (where the read ran) and `Route.Fallback` is `true`.
7. **`PinnedUntil(ctx) time.Time` is added.** It returns the session's pin end (zero without a session).
   - The spec has an application carry a pin across requests with `PinUntil`, but it would have no way to learn the time to store; this gives it.
   - A session stores its pin end, not its last write: a successful write sets it to `now + the DB's window`, never lowering it, and `PinUntil(ctx, t)` raises it to `t`. `PinUntil` on a context without a session does nothing.
   - The comparison on a read is `time.Now().Before(until)`. It is made only when the context has a session.
8. **Inside a transaction:**
   - A statement whose context names no shard (no `OnShard`, no tenant) runs on the transaction's shard.
   - One whose context names another shard fails with `velox: <Entity>: statement for shard "X" in a transaction on shard "Y"`. That error does not wrap `ErrNoShard`, because a shard was found.
   - A `WithShardFor` error fails the statement.
   - The commit of a transaction that made a successful write marks the session of the context given to `Tx`. A savepoint rolled back does not clear the mark (conservative).
9. **`SQL(ctx)` runs the route stage too.** It returns `ErrNoShard` and the transaction-shard error as a run would, and sets `Statement.Route`. It never fails over, because nothing is sent.
10. **`db.Tx(ctx, fn, ReadOnly())` runs on the primary,** like every transaction (spec §2's table). Read-only transactions on replicas are out of scope.
11. **Every DB, routed or not, sets `Route{Replica: -1}`** for its statements, with `Shard` set on a sharded DB. A hook never sees `Replica: 0` meaning "replica 0" on a DB without replicas.

## Review Focus

1. **Parent and children from different replicas.** A `With` load after a read on replica 1 must run on replica 1. Task 1's `TestWithLoadsRunWhereTheQueryRan` pins it.
2. **A cancelled context blamed on a replica.** A cancelled or timed-out read must neither fall over nor put the replica in back-off. Task 3's `TestCancelledReadIsNotAFailover` pins it.
3. **Even spread under concurrency.** Among N goroutines × M reads over k healthy replicas, each replica gets M·N/k ± 1 reads, and nothing races. Task 1's `TestRoundRobinUnderConcurrency` pins it.
4. **Misconfiguration found at open, not at the first statement.** Every panic in Global Constraints is asserted by Task 1's and Task 4's `TestRoutingMisconfigurationPanics` cases.
5. **A dry run that would be refused.** `SQL(ctx)` on a sharded DB with no shard returns `ErrNoShard` and runs no `WithShardFor` side effect twice. Task 4's `TestDryRunIsRouted` pins it.
