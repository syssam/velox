# Schema DSL, Plan 3: the generator — Implementation Plan

> **Note, 2026-10-19.** Plan 4 (`2026-10-16-schema-4-finish.md`) removed the old struct scanner. velox-gen now has one mode, so Ruling 1 (coexistence), the old-mode line of the command table and the old-mode steps below are superseded; they stay as the record of how plan 3 was built. The example of descriptor reads (Ruling 5) is also changed: the generator numbers its reads from `d0`, and `UpdateDefault` fills on update only.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** velox-gen writes the `gen` package from a schema package. The package holds the entity structs, typed enums, handles, and `Desc` metadata literals with their validators, defaults and relations; join entities for many-to-many edges; and the binding of the `Policy()` and `Hooks()` methods users write beside it. The internal test model is then generated from a DSL schema.

**Architecture:**
- `internal/gen` gains two steps:
  - **Lower:** the resolved `Graph` (plan 1) becomes an output model. It holds Go names and types, handle kinds, enum constants, join entities and the code fragments for defaults and checks.
  - **Render:** writes one file per entity plus `velox.go`, formatted with `go/format`.
- **velox-gen gains a new mode:**
  - `velox-gen [-out dir] [-package name] [-check] ./schema` loads, builds and writes;
  - `velox-gen verify -out dir ./schema` runs `CheckEntity` on every generated entity.
- **The old struct scanner stays for `./...`-style patterns until plan 4**, which migrates the examples, bench/scale and the remaining test entities and deletes the old path. *(Superseded: plan 4 deleted it; `./...` is now an error.)*

**Tech Stack:** Go 1.27, standard library (`go/format`, `go/parser`, `text/template` or `strings.Builder`), `internal/tempmod`, SQLite (`modernc.org/sqlite`) for the end-to-end test.

**Spec:** `docs/history/specs/2026-10-15-schema-design.md`:
- §2: generated code;
- §3: binding behaviour;
- §4: velox-gen, generate and `-check`;
- §7: generator golden tests, determinism, ports.

Plans 1 and 2 (merged) produced the `Graph` (`internal/gen/graph.go`) and the runtime's `Desc[E]` path (`desc.go`, `hook.go`, `relation.go`). The shape to generate is the hand-written `internal/testmodel/*_desc.go` and the root `desc_model_test.go`.

## Global Constraints

- **Go 1.27.** The root module stays standard-library only; `internal/gen` uses `go/parser` and `go/format`, not `golang.org/x/tools`.
- **Nothing runs at program start, in velox or in generated code.**
  - Every package-level `var` velox-gen writes is a composite literal or a zero value.
  - A regexp, a schema descriptor read or anything else computed is done inside the `Desc` function, which runs on first use.
- **Generated code shape.** It follows `internal/testmodel/ticket_desc.go`:
  - a handles variable;
  - a `MetaOnce`;
  - `VeloxMeta` calling `Load`;
  - a `<label>Desc()` function returning `velox.Desc[E]`;
  - `Addr` and `RelAddr` as allocation-free `switch` statements;
  - `Tenant` always written (`-1` for none).
- **Policy and hooks.** `Policy` and `Hooks` are bound only when the user's own files in the output directory declare the method:

  ```go
  Policy: func() velox.BoundPolicy { return velox.BindPolicy((*User)(nil).Policy()) },
  ```

- **Determinism.** The same Graph and inputs give byte-identical files. The output is `gofmt`-clean (`go/format.Source`).
- **Errors.**
  - velox-gen prints `velox-gen: <err>` and exits 1, writing nothing when any entity has a problem.
  - Generator errors name the schema: `schema User: field "x": …`, as `internal/gen.Error` does.
- **Headers.**
  - Every generated file starts with `// Code generated by velox-gen. DO NOT EDIT.` followed by a blank line.
  - velox-gen writes, rewrites and deletes only files that start with it.
- **Clean.**
  - `gofmt`, `go vet` and golangci-lint v2.14.0 pass in the root module, `cmd/velox-gen`, `example` and `contrib/otel`.
  - `go test -race ./...` passes in all four.
  - Tests that build a temporary module skip under `-short`.
- **No machine-specific paths in committed files.** Use `GOCACHE=<scratchpad>/velox2-gocache` and `GOFLAGS=-p=2` only in your shell, because the machine is memory-constrained.
- **Commits** end with a blank line and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push.

## Rulings this plan makes on the spec

1. **Coexistence until plan 4.** *(Superseded by plan 4: velox-gen has one mode, and a pattern that names no schema package is an error, "no schemas in …".)* velox-gen picks its mode from its argument.
   - A single-package pattern whose package declares schemas (types embedding `schema.Schema`, found by `internal/gen`'s `discover`) runs the new generator.
   - Any other pattern runs the old struct scanner, exactly as today.

   Plan 4 deletes the old scanner, migrates the examples and bench/scale, and drops this rule. Why: the examples and bench/scale use the old scanner, and every task must leave CI green.
2. **An `Optional` field is a pointer in Go,** like `Nillable`, because its column is NULL-able. velox scans a NULL only into a pointer: `scanRow` scans straight into the field, and `database/sql` and pgx refuse NULL into a `string`. `Graph.Field.Pointer` is extended by this rule at lowering time.
   - If wrong: a ported ent schema's `Optional()` fields become `*T`, where ent gives `T`. Recorded in the followups as an ent difference.
3. **Enums.**
   - An enum without `GoType` becomes `type <Entity><Field> string`, for example `UserRole`.
   - Its constants are `<Entity><Field><pascal(Name)>`, for example `UserRoleViewer = "viewer"`, with a `Values() []string` method in declaration order.
   - An enum with `GoType` uses the user's type and generates no type.
4. **Join entities.**
   - Each many-to-many join table becomes an entity named `pascal(singular(table))`: `user_groups` → `UserGroup`.
   - Its fields are the two columns, `pascal(column)` each (`UserID`, `GroupID`), typed as the IDs they reference. The primary key is both columns; `Tenant` is `-1`; it has no relations.
   - Both edges of the pair share it.
   - A name that collides with an entity, a handle variable or another join entity is an error.
5. **Defaults.**
   - A literal `Default` on a bool, number, string or enum field is written as a typed Go literal of the field's element type: `int64(5)`, `"x"`, `true`, `UserRoleViewer`, `MyType("x")` for a `GoType`.
   - Every other default is read on first use from the schema package's descriptor and wrapped in `func() any`: `DefaultFunc`, `UpdateDefault`, a time or uuid `Default` function, and a literal `Default` of a bytes, JSON or other field.
   - The descriptor expression is `<sch>.User{}.Fields()[i].Descriptor()`, or `<sch>.User{}.Mixin()[m].Fields()[i].Descriptor()` for a mixed-in field, by `Field.Position`.
   - Each descriptor read happens once, in the setup block at the top of the entity's `Desc` function (which runs once, on first use): `d0 := (&sch.User{}).Mixin()[0].Fields()[0].Descriptor().Default.(func() time.Time)` (the reads are numbered from `d0`), and the column's `DefaultFunc` is `func() any { return d0() }`. A call per row does no descriptor read. (Amended after the whole-branch review: the first version read the descriptor on every call, about 16 allocations per insert for `mixin.Time`.) The decoding of a bytes or JSON default stays per call, so that no two rows share a slice or a map.
   - `gen` therefore imports the schema package, under the alias `sch`, only when some entity needs it.
6. **Validators are code in the `Check` function.**
   - The built-in checks (`NotEmpty`, `MinLen`, `MaxLen`, `Match`, `Range`, `Min`, `Max`, `Positive`, `Negative`, `NonNegative`) and an enum's membership check are written inline.
   - `Match` compiles its regexp inside the `Desc` function.
   - `Validate` functions are read from the descriptor, `.Validators[j]` asserted to `func(V) error` with V the builder's value type, and called with the value converted to V.
   - Messages:
     - `must not be empty`
     - `length is less than N`
     - `length is more than N`
     - `does not match <pattern>`
     - `is less than N`
     - `is more than N`
     - `is not positive`
     - `is not negative`
     - `is negative`
     - `is not one of the values` (enum)

     velox wraps each as `*ValidationError`.
7. **Reserved Go names.** A field or edge whose Go name is `VeloxMeta`, `String`, `GoString`, `Policy` or `Hooks` is an error, because those are methods of the entity. So is a handles variable (`plural(Name)`) that collides with an entity, a join entity or an enum type.
8. **`String()`.** Each entity gets `func (x E) String() string`, with a value receiver, and `func (x E) GoString() string { return x.String() }`. It prints `E(Field=value, …)` with every field except `Sensitive` ones and edges, using `%v` for the values. A `Sensitive` field gets the JSON tag `json:"-"`.
   - The receiver is a value because `All()` returns `[]E`: with a pointer receiver, `%v`, `%+v` or `%v` of a slice of values would print the Sensitive fields through the default struct formatting. `GoString` closes `%#v` the same way.
   - Amended after the whole-branch review.
9. **JSON tags.**
   - A field gets `json:"<name>,omitempty"`.
   - An edge gets `json:"<name>,omitzero"`, so an edge that was not loaded is left out (runtime `One`/`Many` docs).
   - A field's `StructTag` replaces the generated tag.
10. **The stale check is `-check`.**
    - `velox.go` records the model's SHA-256 in a comment (`// Model: sha256:<hex>`) and references `velox.GeneratedCodeIsVersion3`.
    - The spec's "compile-time check that the generated package matches the schema" cannot be done at compile time across packages. `-check`, which regenerates in memory and compares, is that check in CI.
11. **Method detection.**
    - velox-gen parses every `.go` file in the output directory that is not a test and does not start with the header. A method `Policy` or `Hooks` with receiver `*E`, for a generated entity `E`, binds that method. A value receiver `E` is an error, `<file>: E.Policy must have a pointer receiver (func (*E) Policy())`, because the binding calls the method on a nil `*E` (amended after the whole-branch review).
    - A non-test file that declares a type with an entity's name is an error (the user redeclared a generated type).
12. **`GeneratedCodeIsVersion3`** is added to the runtime beside `GeneratedCodeIsVersion2`. Plan 4 removes `2` with the old scanner.

## Review Focus

1. **A schema with no edges, enums or validators** (the simplest case) must generate code that compiles and imports nothing unused. Pinned in Task 2: golden `minimal`.
2. **A mixed-in field's `DefaultFunc` or `Validate`** must be reached through `Mixin()[m]`, not through `Fields()`. Pinned in Task 3: `TestGeneratedRunsOnSQLite` uses `mixin.Time` and a mixin with a validator.
3. **A user file that declares `Policy()` with a wrong signature** must fail to compile, not be ignored. Pinned in Task 3: `TestWrongPolicySignatureDoesNotCompile`.
4. **Regenerating when nothing changed** must write nothing, and `-check` must exit 0. A schema change must make `-check` exit 1 naming the file. Pinned in Task 4: `TestCheckAndRewrite`.
5. **Two schemas whose generated names collide** (an enum type `UserRole` against a schema named `UserRole`; a join entity against an entity) must give one clear error and write nothing. Pinned in Task 1: `TestLowerCollisions`.

### Task 1: Lowering the Graph to an output model

**Files:**
- Create: `internal/gen/out.go`, `internal/gen/lower.go`, `internal/gen/lower_test.go`

**Interfaces:**
- Consumes: `Graph`, `Entity`, `Field`, `Edge`, `Rel`, `Index` (`internal/gen/graph.go`), plus `pascal`, `snake`, `plural` and `singular` (`internal/gen/names.go`).
- Produces (used by Tasks 2–5):

```go
// Config says where generated code goes and what the user's files declare.
type Config struct {
	Package    string           // the generated package's name, default "gen"
	SchemaPath string           // the schema package's import path (Graph.Package)
	Bound      map[string]Bound // per entity name: which methods the user's files declare
}

type Bound struct{ Policy, Hooks bool }

// Out is everything Render writes.
type Out struct {
	Package   string
	Entities  []*OutEntity // the graph's, then the join entities, sorted by Name
	Enums     []*OutEnum   // sorted by type name
	Hash      string       // sha256 of the Graph's JSON, hex
	NeedsSch  bool         // some entity reads the schema package
	SchemaPath string
}

type OutEntity struct {
	Name, Label, Handles, Table, TableSchema string // Handles = plural(Name), e.g. "Users"
	Fields      []*OutField
	Rels        []*OutRel
	PrimaryKey  []int
	Tenant      int // -1 none
	Indexes     []OutIndex // columns as field indexes
	Join        bool       // a many-to-many join entity
	Bound       Bound
	Imports     []string   // import paths this entity's file needs, sorted
	CheckCode   string     // the body of Check's switch, "" when none
	CheckSetup  string     // statements run once inside Desc before the literal (regexps, validator funcs), "" when none
}

type OutField struct {
	GoName, Column, Name string
	GoType               string // as written in the struct, e.g. "*time.Time", "UserRole"
	ElemType             string // GoType without the pointer
	Pointer              bool
	Handle               string // e.g. "velox.NullOrderedCol[User, time.Time]"
	Tag                  string // the struct tag, including backquotes
	Comment              string
	Sensitive, Immutable bool
	DefaultCode          string // "" or a Go expression for ColumnDesc.Default
	DefaultFuncCode      string // "" or "func() any { … }"
	UpdateDefaultCode    string
}

type OutRel struct {
	GoName, Name, Target string
	Many                 bool   // Many[T] (O2M, M2M) or One[T] (O2O, M2O)
	Desc                 string // the velox.EdgeTo/EdgeThrough expression
}

type OutIndex struct {
	Columns []int
	Unique  bool
}

type OutEnum struct {
	Type   string   // e.g. "UserRole"
	Consts []string // e.g. "UserRoleViewer"
	Values []string // stored values, in declaration order
}

func Lower(g *Graph, cfg Config) (*Out, error)
```

**The mapping:**

| Field `Type` | Go element type |
|---|---|
| bool, int…, uint…, float… | the type, or `GoType.Ident` |
| string | `string`, or `GoType.Ident` |
| enum | the generated enum type (Ruling 3), or `GoType.Ident` |
| bytes | `[]byte`, or `GoType.Ident` |
| time | `time.Time`, or `GoType.Ident` |
| uuid, json, other | `GoType.Ident` (always set) |

- **Pointer:** a field is a pointer when `Pointer || Optional` (Rulings 2 and plan 1 Ruling 4).
  - It is never a pointer when the element type is a slice or map (`[]byte`, `[]string`, maps), because nil already means NULL.
  - The ID is never a pointer.
- **Handle kinds:** follow `cmd/velox-gen/classify.go` by kind.
  - `time.Time` is `OrderedCol`.
  - An integer or float kind is `NumberCol`.
  - A string kind (string, enum, a `GoType` of string kind) is `StringCol`.
  - Anything else is `Col`.
  - A pointer field takes the `Null` form, whose value type is the element.
  - Use `GoType.Kind` to decide the kind of a `GoType`.
- **Imports** come from `GoType.Imports` plus `time` for time fields.
  - Two different import paths whose package names collide are an error: `schema User: field "x": imports a and b both named n`.
  - The package name is the last element of `GoType.Ident`'s qualifier.
- **Relations:**
  - **Owner and target columns.** For each edge, find the owner's and target's column indexes:
    - M2O, or O2O where the owner holds the key: the owner's FK field, and the target's ID.
    - O2M, or O2O where the target holds it: the owner's ID, and the target's FK field. `Edge.Field` names the FK field and `Rel.Table` says whose table holds it.
  - **The expression:** `velox.EdgeTo[T]("GoName", ownerCol, targetCol)`.
  - **M2M:**
    1. Synthesize or reuse the join entity (Ruling 4), with fields in the order of the assoc edge's `Rel.Columns`.
    2. Write `velox.EdgeThrough[J, T]("GoName", ownerID, joinOwner, joinTarget, targetID)`.
    3. `joinOwner` and `joinTarget` are J's field indexes of the columns `Rel.Columns[0]` and `Rel.Columns[1]` as seen from this edge (plan 1: `Columns[0]` is always the owner's).
- **Checks** (Ruling 6). For each column with checks, an enum, or validators, write a `case <i>:` block.
  - It asserts `x := v.(<ElemType>)` (the runtime passes the element value, never nil, for a pointer field).
  - Then the checks:
    - `NotEmpty` on string: `x == ""`.
    - `MinLen`/`MaxLen`: `len(x)`.
    - `Match`: `!reN.MatchString(string(x))`, with `reN := regexp.MustCompile(<quoted pattern>)` in `CheckSetup`.
    - The numeric checks compare against the arg literal converted to the element type.
    - An enum: a `switch` over the constants.
    - A validator: `if err := vN(<V>(x)); err != nil { return err }`, with `vN := <descriptor>.Validators[j].(func(<V>) error)` in `CheckSetup`, where V is `string`, `[]byte` or the number's base type.
  - Each failing check returns `errors.New("<message>")` or `fmt.Errorf(...)`.
- **Validation (Ruling 7):** reserved names, handle/entity/enum/join collisions. Errors are collected and joined like `Build`'s.

**Files:**

- Modify: `doc.go` (root): add `GeneratedCodeIsVersion3`

**Interfaces:**
- Consumes: `Out` (Task 1).
- Produces:

```go
type File struct {
	Name string // e.g. "user_velox.go", "velox.go"
	Data []byte // gofmt-formatted
}

// Render writes one file per entity, <label>_velox.go (join entities too),
// and velox.go: the enums and the model's hash.
func Render(o *Out) ([]File, error)

// Generate is Lower then Render.
func Generate(g *Graph, cfg Config) ([]File, error)
```

**A file per entity**, in this order:
1. The header.
2. `package <Package>`.
3. The imports: `velox`, its own imports, `errors`/`fmt`/`regexp` when its checks use them, and `sch "<SchemaPath>"` when the entity reads the descriptor.
4. `const _ = velox.GeneratedCodeIsVersion3`.
5. The struct. Its doc comment is `// <Name> is the entity of schema <Name>.`, or the schema's `Comment` annotation's text. Its fields are in order, each with its tag and comment; then one field per edge, of type `velox.One[T]` or `velox.Many[T]`.
6. The handles variable. Its type is an anonymous struct of `<Handle>` per field and `velox.Rel[E, T]` per edge. Its value has `{I: i}` per field and `{I: j}` per edge. Use `ticket_desc.go`'s layout.
7. `var <label>Meta velox.MetaOnce[E]`.
8. `func (*E) VeloxMeta() *velox.Meta[E] { return <label>Meta.Load(<label>Desc) }`.
9. `func <label>Desc() velox.Desc[E]` with this body:
   - `CheckSetup` statements, if any.
   - `return velox.Desc[E]{…}` with these fields:
     - `Policy`/`Hooks`, only when bound;
     - `Table`, and `Schema` when set;
     - `Columns` (a `velox.ColumnDesc` per field, with `Field`, `Name` and the non-empty default codes, `Immutable` and `Sensitive`);
     - `PrimaryKey`;
     - `Tenant`;
     - `Indexes`;
     - `Relations`;

- Produces:

```go
// Methods reads the non-test .go files in dir that do not start with
// velox-gen's header, and reports which of entities have a Policy or Hooks
// method (receiver *E; a value receiver is an error). A file that declares a type named like an
// entity is an error (Ruling 11). A missing dir is no files.

```

**The command:**

```
velox-gen [-out dir] [-package name] [-check] [package]       new mode, when package declares schemas (Ruling 1)
velox-gen verify -out dir [package]                           new mode: CheckEntity on every generated entity
velox-gen describe [-json] [package]                          as today
velox-gen [-check] [-ordered …] [-number …] [patterns]        old mode, otherwise (until plan 4; removed by it)
```

- **Defaults:** `-out ./gen`, `-package` is the base name of `-out`, and the package is `./schema`.
- **Mode selection:**
  1. If there is exactly one pattern, and `go list` (through `gen.Load`'s first step, factored out as `gen.Inspect(dir, pattern, env) (importPath string, schemas []string, err error)`) finds schemas in it, use the new mode.
  2. If the pattern names no package with schemas, the old mode runs. *(Plan 4: it is an error.)*
  3. `-out` given with an old-mode pattern is an error: "-out needs a schema package". *(Plan 4: gone with the old mode.)*
- **Generate:**
  1. Load and Build.
  2. `Methods(out, entityAndJoinNames)`.
  3. `Generate` with `Config{Package, SchemaPath, Bound}`.
  4. Under `-check`: compare with the files on disk.
     - A differing or missing file, and a generated file on disk with no counterpart, are reported as `velox-gen: <path> is out of date`, followed by one line `velox-gen: run go tool velox-gen <args>`, and exit 1.
     - Otherwise exit 0 and write nothing.
  5. Otherwise:
     - write each changed file, creating `out`;
     - delete generated files with no counterpart;
     - print each written or deleted path, relative to the working directory;
     - never touch a file without the header. A file without the header at a path velox-gen would write is an error: `<path> was not written by velox-gen; move it`.
- **Verify:** builds a program in a `.velox-verify-*` directory, as the old verify does. It imports the `-out` package (its import path from `go list`) and calls `velox.CheckEntity[gen.E]()` for every entity and join entity. Reuse `cmd/velox-gen/verify.go`'s runner.
