# velox-graphql on graphql-go: design spec

**Status: parked (2026-11-03).** The user chose to support gqlgen and
github.com/syssam/graphql-go, with graphql-go the default, then set GraphQL
aside to focus on the ORM. Nothing here is built. Prototype paths below were
in a session scratchpad and are gone.

Status: proposal, 2026-11-03. Base: branch gql-untyped (a7a80cfe), graphql-go
3e0050b (2026-10-29, untagged). Decision taken by the user: velox's GraphQL
supports gqlgen and github.com/syssam/graphql-go, and graphql-go is the
default. Pre-1.0: nothing is kept for compatibility.

## 0. Findings this spec rests on

Each was checked by reading code or by running a prototype. The prototype is
in the scratchpad (`ggproto/`, `scalegg/`); it binds examples/graphql's
generated `gen` package to graphql-go by hand.

- `graphql.NewSchema` accepts velox.graphql unchanged, `@goField` and
  `@goModel` included, once every type is bound (ggproto `TestSchema`).
- A nested query (20 users, 5 posts each, author, tags) runs and returns the
  right data. It sends 241 statements: the batch table and Selected never
  engage, because gqlimpl asks gqlgen's `graphql.GetFieldContext`, which is
  nil under graphql-go. It should be 5, one per edge per level plus the
  count, as examples/graphql's nested benchmark is under gqlgen; phase 2
  gates on equal counts.
- `Input[T]` derives names with `AuthorID → authorId`. velox's SDL says
  `authorID`, `tagIDs`. Without a `graphql:"…"` tag NewSchema fails:
  `input field PostWhereInput.authorIdIn is not defined in the schema`.
- A Go `bool` cannot back a nullable `Boolean` (`clearTags`). NewSchema fails
  unless the input takes `graphql.ZeroForNull()`.
- A bound directive written on an input field fails NewSchema:
  `UserWhereInput.email: @admin is bound and written here, where a directive
  never runs` (directive.go `rejectDirectivesThatNeverRun`). velox copies a
  field's directives onto its where and mutation input fields on purpose.
- `FieldContext.Field` is the `*ast.FieldDefinition`; the query's
  `*ast.Field` (`planField.ast`) is unexported. Selection sets are memoised
  per (parent type, AST nodes): one fragment used twice is one `Selection`.
- `OperationContext` has `Operation`, `Doc`, `Variables`, but no schema.
  `FieldContext.ArgumentMap(vars)` keeps explicit nulls as nil map values.
- Resolve fields run one goroutine each unless bound with `graphql.Inline()`.
  A FieldInterceptor wraps every field, pure ones too, through `any`.
- At N=100 (mkscale.sh shape) NewSchema takes 28 ms for 623 types. The
  bindings add about 12-14 s CPU and 0.85 GB peak to the `gen` compile
  (section 4).

## 1. Shape

### Decision: velox-graphql emits the bindings itself

velox-graphql writes `gen/velox.graphql` and, per entity, Go that calls
graphql-go's constructors. It does not hand the SDL to gqlc.

| Criterion | Emit bindings (chosen) | SDL + gqlc autoBind |
|---|---|---|
| API | `gen.GraphQL()`, one option; no tool, no config | gqlc.yaml with autoBind, scalar models, field renames; a `graph` package with a Resolver to implement |
| Correctness | velox knows `id` is `IDGQL`, `author` is `AuthorGQL(ctx)` | gqlc matches by name: `id` would bind to the int64 `ID` field and write a local key, silently; `TagsGQL` matches nothing |
| Build | one closure per SDL field, in `gen`, which recompiles on any schema change anyway | the same constructor calls, so the same instantiation cost (section 4), in more packages, plus gqlc's export-data load per run |
| Runtime | identical: both end in `Object`/`Field`/`Resolve` closures | identical |

gqlc stays useful for the application's own SDL that velox does not write.

### Files

The plugin splits each entity's Go into a shared file and a backend file.

- `gen/<label>_gql.go`, both backends: the connection, edge, order and where
  types, `Pred`/`PredicateGQL`, `<Edge>GQL` methods, `<Plural>Connection(Of)`,
  the Create/Update inputs and their methods, `IDGQL`, `IsNode`. Unchanged but
  for one thing: every input-struct field carries `graphql:"<sdlName>"`.
  gqlgen binds input fields by name; the e2e matrix proves the tag harmless.
- `gen/<label>_graphqlgo.go`, graphql-go only: the bindings below and the
  connection-arguments struct.
- `gen/<label>_gqlgen.go`, gqlgen only: the enums' `MarshalGQL`/`UnmarshalGQL`.
- `gen/graphql_graphqlgo.go`, graphql-go only: `GraphQLSDL()` (velox.graphql
  embedded), `GraphQL()` (every entity's option, each with its QueryField,
  the adapter's shared types, Query.node and Query.nodes).

Per-entity functions stay unexported. NewSchema fails on any unbound type, so
an application cannot use one entity's option without the others.

### Generated Go for Post (`gen/post_graphqlgo.go`)

```go
// Code generated by velox-gen. DO NOT EDIT.

package gen

import (
	"context"
	"time"

	graphql "github.com/syssam/graphql-go"

	"github.com/syssam/velox"
	"github.com/syssam/velox/contrib/graphql/veloxgql"
)

const _ = veloxgql.GeneratedCodeIsVersion12

// PostsArgs are the arguments of a connection to Post nodes: Query.posts and
// the edges User.posts and Label.posts.
type PostsArgs struct {
	After   *veloxgql.Cursor
	First   *int
	Before  *veloxgql.Cursor
	Last    *int
	OrderBy []*PostOrder
	Where   *PostWhereInput
}

// ConnectionOf is PostsConnectionOf of q with a's arguments.
func (a PostsArgs) ConnectionOf(ctx context.Context, q velox.Query[Post]) (*PostConnection, error) {
	return PostsConnectionOf(ctx, q, a.After, a.First, a.Before, a.Last, a.OrderBy, a.Where)
}

// postGraphQL binds Post's GraphQL types. Its edges and connection fields
// run inline: one statement serves a whole batch, so a goroutine per row
// would only wait.
func postGraphQL() graphql.SchemaOption {
	return graphql.Options(
		graphql.Object[Post]("Post",
			graphql.Field("id", (*Post).IDGQL),
			graphql.Field("title", func(x *Post) string { return x.Title }),
			graphql.Field("status", func(x *Post) PostStatus { return x.Status }),
			graphql.Field("views", func(x *Post) int64 { return x.Views }),
			graphql.Field("publishedAt", func(x *Post) *time.Time { return x.PublishedAt }),
			graphql.Resolve("author", func(ctx context.Context, x *Post) (*User, error) { return x.AuthorGQL(ctx) }, graphql.Inline()),
			graphql.ResolveArgs("tags", func(ctx context.Context, x *Post, a LabelsArgs) (*LabelConnection, error) {
				return x.TagsGQL(ctx, a.After, a.First, a.Before, a.Last, a.OrderBy, a.Where)
			}, graphql.Inline()),
		),
		graphql.Enum("PostStatus", map[PostStatus]string{
			PostStatusDraft:     "DRAFT",
			PostStatusPublished: "PUBLISHED",
		}),
		graphql.Object[PostConnection]("PostConnection",
			graphql.Resolve("edges", func(ctx context.Context, c *PostConnection) ([]*PostEdge, error) { return c.Edges(ctx) }, graphql.Inline()),
			graphql.Resolve("pageInfo", func(ctx context.Context, c *PostConnection) (*veloxgql.PageInfo, error) { return c.PageInfo(ctx) }, graphql.Inline()),
			graphql.Resolve("totalCount", func(ctx context.Context, c *PostConnection) (int, error) { return c.TotalCount(ctx) }, graphql.Inline()),
		),
		graphql.Object[PostEdge]("PostEdge",
			graphql.Field("node", func(e *PostEdge) *Post { return e.Node }),
			graphql.Field("cursor", func(e *PostEdge) veloxgql.Cursor { return e.Cursor }),
		),
		graphql.Input[PostOrder]("PostOrder"),
		graphql.Enum("PostOrderField", map[PostOrderField]string{
			PostOrderFieldTitle: "TITLE",
			PostOrderFieldViews: "VIEWS",
		}),
		graphql.Input[PostWhereInput]("PostWhereInput"),
		graphql.Input[CreatePostInput]("CreatePostInput"),
		graphql.Input[UpdatePostInput]("UpdatePostInput", graphql.ZeroForNull()),
		graphql.Args[PostsArgs](),
		graphql.Query(graphql.ResolveArgs("posts", func(ctx context.Context, _ graphql.Root, a PostsArgs) (*PostConnection, error) {
			return PostsConnection(ctx, a.After, a.First, a.Before, a.Last, a.OrderBy, a.Where)
		})),
	)
}
```

Notes on it:

- Node: `GraphQL()` binds `graphql.Interface[veloxgql.Noder]("Node")` once;
  graphql-go resolves `node`/`nodes` results by dynamic Go type (`*Post` →
  `Post`). Query.node and Query.nodes call node_gql.go's `Node`/`Nodes`.
- The where and mutation inputs are the shared structs, decoded by `Input[T]`
  from their tags, e.g. `AuthorIDIn []string \`graphql:"authorIDIn"\``.
  Every field carries one, even where the derived name matches.
- Enums bind by `graphql.Enum` maps. A stored value outside the enum is a
  field error, where gqlgen's marshaler wrote it raw.
- `LabelsArgs` is emitted in tag_graphqlgo.go. `(*Post).IDGQL` is a method
  expression: no closure.

### What the application writes (examples/graphql's main, graphql-go)

```go
//go:embed graph/*.graphql
var appSDL embed.FS

type createPostArgs struct{ Input gen.CreatePostInput }

func server(db *velox.DB) (http.Handler, error) {
	s, err := graphql.NewSchema(
		graphql.Sources(gen.GraphQLSDL(), graphql.SDLFS(appSDL, "graph/*.graphql")),
		gen.GraphQL(),
		graphql.Mutation(
			graphql.ResolveArgs("createPost", func(ctx context.Context, _ graphql.Root, a createPostArgs) (*gen.Post, error) {
				viewer, err := Author(ctx)
				if err != nil {
					return nil, err
				}
				return a.Input.Create(ctx, &gen.Post{AuthorID: viewer})
			}),
			// updatePost (updatePostArgs: ID, Input), deletePost and the
			// label and user mutations alike: one call each.
		),
		graphql.Query(graphql.ResolveArgs("publishedPosts",
			func(ctx context.Context, _ graphql.Root, a gen.PostsArgs) (*gen.PostConnection, error) {
				db, err := veloxgql.DBFromContext(ctx)
				if err != nil {
					return nil, err
				}
				return a.ConnectionOf(ctx, db.Query[gen.Post]().Where(gen.Posts.Status.EQ(gen.PostStatusPublished)))
			})),
		graphql.Object[gen.User]("User", graphql.Field("initials", initials)),
		graphqlgo.Directive("admin", admin), // see G1
	)
	if err != nil {
		return nil, err
	}
	exec := graphql.NewExecutor(s, graphqlgo.With(s, db, veloxgql.WithLimits(limits)))
	return graphqlgo.Handler(exec, limits), nil
}
```

`graphqlgo.With` is one `graphql.ExecutorOption` that applies the velox
interceptors, the error presenter and graphql-go's own limits mapped from
`veloxgql.Limits` (section 2). `graphqlgo.Handler` is `gqlmux.New` with
`gqlhttp.WithMaxBodyBytes(MaxBodyBytes)`. It takes `s` because
OperationContext has no schema (ask A3).

## 2. What is shared and what is per-backend

### SDL

One writer, `internal/sdl`, with a `Backend` field. Differences:

| SDL item | gqlgen | graphql-go |
|---|---|---|
| `@goField`/`@goModel` declarations and uses | written | left out (graphql-go accepts them, but they mean nothing there) |
| `extend type __Type @goModel(…)` introspection binds | written when needed | left out |
| application directives on input fields | written | left out until A1; enforced by generated metadata instead (G1) |
| everything else | same | same |

The Go-name collision rules (`typeNames.goNames`) exist for gqlgen's
autobind. They stay for both, so a schema generates under either backend.

Scalars: graphql-go builds in `Int` for int, int32, int64 and `Float` for
float64, float32. The adapter adds `Int` for int8, int16, uint8, uint16,
uint32, uint, and binds `Time`, `UUID`, `Bytes`, `JSON`, `Uint64`, `Cursor`,
`OrderDirection` and `PageInfo`.

### Runtime layout

```
veloxgql            shared: IDs, Cursor, PageInfo, OrderDirection, Limits,
                    errors and codes, Cost (on gqlparser's AST), document
                    and variable bounds, error classification, Batch,
                    DBFromContext. Imports gqlparser, not an engine.
veloxgql/gqlimpl    engine-agnostic runtime for generated code (as today).
veloxgql/internal/gqlcore
                    batch table, coded errors, and the Engine seam.
veloxgql/graphqlgo  adapter (own module): Engine on graphql-go, scalars,
                    With, Handler, ErrorPresenter, Directive.
veloxgql/gqlgenx    adapter (own module): today's Extension, Setup,
                    presenter, marshal functions and the gqlgen Engine.
```

Both adapters sit under veloxgql so that they may import
`veloxgql/internal/gqlcore`: Go's internal rule goes by import path, across
modules too.

### The seam

gqlimpl reads the running field through one interface, `gqlcore.Engine`,
which the adapter puts in the request's batch table. For the field resolving
in ctx it answers: its object and name ("Post", "tags"); a comparable key
for its occurrence in the operation; `Selected(typ)`; and
`Nulls(input, name)`. Outside a field it answers nothing.

Every gqlgen dependency, and what replaces it on graphql-go:

| Place | gqlgen today | graphql-go |
|---|---|---|
| `Selected` (select.go): what a connection's nodes select, for `Narrow` | `GetFieldContext`, `GetOperationContext`, `CollectFields` over AST fragments, schema interfaces | `FieldFrom(ctx).Selection()`; `edges`/`node` by `Fields()` (all aliases); `ForType(typ)` for `node`/`nodes`; skip `SelectedField.Withheld(ctx)`. Fragments, `@skip`/`@include` are already folded in the plan. Cached per request by `(Selection, typ)` (ask A2 for a stable key) |
| Batch identity (edge.go `batchOf`) | `fc.Object`, `fc.Field.Name`, `fc.Field.Field` (`*ast.Field`), `fc.Field.Selections` | `fc.Object.Name`, `fc.Field.Name`, and `fc.Selection()` as the occurrence key. Two aliases with one shared sub-selection and different arguments then read alone (correct, N+1); A2 fixes it |
| Rows become a group only inside a field (`gqlcore.Add`) | `GetFieldContext != nil` | `FieldFrom != nil`: set for Resolve fields, which every velox field that reads rows is |
| Explicit null (`nullsIn`, behind `Cleared`, `NotNull`) | `fc.Field.Arguments` AST values + variables + schema | `fc.ArgumentMap(oc.Variables)`, walked from `fc.Field.Arguments`' types with the schema given to `With`. Only computed when an input sets a pointer to nil. Not `Omittable`: the shared structs keep `*T` for gqlgen |
| Coded errors (`gqlcore.Error`) | `Extensions() map[string]any`, gqlgen's ExtendedError | add `GraphQLExtensions()` (graphql-go's `ExtensionsProvider`). Codes unchanged: BAD_USER_INPUT, NOT_FOUND, FORBIDDEN, UNAUTHENTICATED, COST_LIMIT_EXCEEDED, INTERNAL_SERVER_ERROR |
| `ErrorPresenter` | `graphql.ErrorPresenterFunc`, gqlerror | `graphql.ErrorPresenter` over the shared `present(err) (code, msg)`. graphql-go's own errors (parse, validation, coercion, `OPERATION_TIMEOUT`, `RESPONSE_TOO_LARGE`) pass through. The Int8 text match goes: velox's own `Int` scalars return BAD_USER_INPUT |
| Enum/scalar marshalers | `MarshalGQL`/`UnmarshalGQL`, `graphql.Marshaler` funcs | `Enum` maps (generated), `Scalar` funcs over shared encode/decode in veloxgql |
| DB, limits, batch table per operation | `InterceptOperation` | `OperationInterceptor`: `withState`, `gqlcore.WithTable` |
| Mutation transaction | `InterceptResponse` commits/rolls back; `InterceptField` serialises | `OperationInterceptor` around `next`: `db.Tx`, rollback when `resp.Errors` is non-empty, data nulled. Serialisation: section 2.5 |
| Cost (`Cost`, MaxCost, MaxIntrospectionCost) | `MutateOperationContext` on `rc.Doc` | same `Cost(schema, oc.Operation, oc.Variables, l)`, in the OperationInterceptor before `next`. Refused: one error, data null, no statement |
| Document bounds (MaxFields, MaxFragments, MaxNameBytes, MaxLiteralBytes, MaxVariableNodes) | own parse in `MutateOperationParameters` | walk `oc.Doc` (already parsed and cached) in the OperationInterceptor, memoised per `*ast.QueryDocument`. MaxTokens and MaxDepth map to `WithMaxTokens`, `WithMaxDepth`, which run before or at planning |
| MaxErrors, Timeout | own counters | `WithMaxErrors`, `WithOperationTimeout`; the presenter maps graphql-go's `OPERATION_TIMEOUT` to velox's `TIMEOUT` |
| MaxResponseBytes | strings, bytes and JSON counted per field | `WithMaxResponseBytes`: all of `data`. A documented change of meaning |
| MaxBodyBytes | `Setup`'s handler | `gqlhttp.WithMaxBodyBytes` via `graphqlgo.Handler` |
| Validation rules (setup.go) | gqlgen validator rules, quiet suggestions | graphql-go's validator, `DisableSuggestions()` |

### 2.5 Batching and concurrency

Keep velox's batch table; do not use graphql-go's `loader`.

- The batch is the rows one statement read; the first edge call on any of
  them reads for all. It needs no wave and no goroutine, and its key (row
  scope, DB, MaxList, WithBatchScope) has no loader equivalent.
- velox binds every field that reads rows with `graphql.Inline()`. A page's
  edges run in order on one goroutine: the first reads the batch, the rest
  read memory. Sibling edges (author, tags) run one after the other: one
  round trip each, the floor batching gives anyway. Phase 4 measures Inline
  against concurrent; Inline stays unless it loses on Nested.
- An application's own Resolve field can still reach a batch concurrently.
  A caller waiting on another's batch calls `oc.Waves().Park()`/`Unpark()`,
  so an application loader's wave is not held up by velox waiters.
- A mutation's transaction must not run two statements at once. Interim for
  application fields under a mutation: `graphqlgo.WithSerialMutations()`
  installs a FieldInterceptor that locks per operation (Park/Unpark around
  the lock). It puts every field, queries' too, on the type-erased path, so
  it is opt-in. Ask A4 removes it.

## 3. Package layout and modules

Modules (today five; this adds two):

| Module | Requires | Holds |
|---|---|---|
| `contrib/graphql` | velox, gqlparser | annotations, cmd/velox-graphql, veloxgql, gqlimpl |
| `contrib/graphql/veloxgql/graphqlgo` (new) | contrib/graphql, graphql-go | package `graphqlgo` |
| `contrib/graphql/veloxgql/gqlgenx` (new) | contrib/graphql, gqlgen | package `gqlgenx` |

A gqlgen application requires gqlgenx and never has graphql-go in its
module graph; a graphql-go application the other way round. contrib/graphql
drops gqlgen (today it requires gqlgen v0.17.86 and gqlparser v2.5.59;
graphql-go requires gqlparser v2.5.59 too). `deps_test.go` asserts that
contrib/graphql imports neither engine; the e2e tests move to the adapters.

The backend is a plugin option:

```
go tool velox-gen -out gen -plugin velox-graphql ./schema                    # graphql-go
go tool velox-gen -out gen -plugin velox-graphql:backend=gqlgen ./schema
```

A plugin option, not a schema annotation: the schema package is shared by
servers and jobs, and the backend is a property of the server's build. Any
other value, or any other option, fails the run as today.

## 4. Measurement plan and targets (N=100)

Shape: scratchpad `mkscale.sh` (100 entities: name, amount, created_at, a
unique `prev` edge, a `next` connection, where, order, QueryField), APPMUT=1
for mutations. Per-package compile CPU and peak RSS with `tx.sh` and a nonce
file, median of three, load noted.

Prototype: `mkggo.sh` writes section 1's bindings for that shape without
mutations; `measgg.sh` times `gen`. Two runs each at load average 55-75:
CPU ±15%, RSS firmer.

| `gen` compile at N=100 | user CPU | peak RSS |
|---|---|---|
| without bindings (what gqlgen mode compiles) | 6.5-7.2 s | 0.52 GB |
| with bindings | 18.7-21.2 s | 1.37-1.41 GB |
| with bindings, constructors behind `//go:noinline` velox wrappers | 16.5-17.2 s | 1.17-1.27 GB |
| with bindings, `-gcflags=gen=-l` (no inlining; baseline 6.1 s, 0.51 GB) | 12.3-13.3 s | 0.95-0.98 GB |

Text of `gen`: 5.26 MB, 2.84 MB of it graphql-go instantiations
(`registerObjectShapes` 839 KB in 2828 functions, `Enum` 565 KB, `Object`
347 KB, `Input` 323 KB). So today graphql-go mode is about 20 s and 1.4 GB
where gqlgen mode is about 7 s for `gen` plus 25 s and 1.9 GB for `graph`:
roughly 40% less CPU and 25% less peak, not an order of magnitude. Wrappers
on velox's side recover little; the rest is per-shape code inside
graphql-go (ask A7). The `-l` row is a proxy for what A7 can reach. The
prototype has no mutations; APPMUT=1 adds two `Input` bindings per entity,
so phase 4 remeasures both backends with it before any figure is final.

| Measure | gqlgen (today) | graphql-go target |
|---|---|---|
| `graph` package compile | ~25 s CPU, 1.9 GB | no such package |
| `gen` compile, bindings included | ~7 s, 0.5 GB | today ≤ 22 s, ≤ 1.5 GB; with A7 ≤ 13 s, ≤ 1.0 GB |
| velox-gen + plugin wall time | baseline | ≤ baseline + 10% |
| App package (APPMUT=1: 200 mutation resolvers) | gqlgen resolvers file | ≤ 3 s CPU |
| NewSchema | 0 | ≤ 100 ms, ≤ 30 MB retained |
| Binary size | baseline | ≤ gqlgen's |

Runtime: port `testdata/bench_inner_test.txt` (List50, List50Count, Nested,
Where, Node, Nodes20) to a graphql-go twin, run by `TestGeneratedBench` with
`VELOX_GQL_BACKEND`. Compare with benchstat, ten runs each, GOMAXPROCS 1
and default. Targets: statements per request equal to gqlgen's on every
benchmark; ns/op ≤ gqlgen's on every one; allocs/op on Nested ≤ 60% of
gqlgen's. examples/graphql's `nestedAllocsBudget` gets a graphql-go figure.

## 5. Phases

Each phase ends with `bash scripts/ci-local.sh` green, and with the gate.

1. **Seam, no behaviour change.** `gqlcore.Engine`; contrib/graphql stops
   importing gqlgen; gqlgen code moves to gqlgenx; scalars split into shared
   encode/decode and gqlgen wrappers. Tests: every existing test, moved, same
   assertions. Gate: `deps_test`; Nested statements and allocs within 2%.
2. **graphqlgo adapter.** Engine, scalars, `With` (state, table, cost,
   document bounds, tx), presenter, Handler, Park/Unpark,
   WithSerialMutations, input-directive guards. Tests: a parity suite on a
   hand-bound examples/graphql (as ggproto), same queries through both
   adapters: paging, cursors, where, node(s), statement counts, explicit
   null, cost refusal, rollback, policies, scope. Gate: identical JSON and
   codes; `-race` clean with concurrent application fields.
3. **Generator.** `backend` option, sdl `Backend`, split files, input tags,
   `GeneratedCodeIsVersion12` and a CHANGELOG line, goldens for both;
   examples/graphql on graphql-go, a gqlgen app kept as e2e testdata. Gate:
   e2e matrix over both backends and every annotation; staleness checks.
4. **Measure** section 4. Gate: targets met, or the gap and its cause go in
   the ADR.
5. **Docs.** ADR "graphql-go is the default engine"; doc.go per backend;
   coverage floors, ci-local.sh and ci.yml for both new modules
   (`TestCILocalMirrorsCI`); API snapshots. Gate: CI mirror green.

## 6. Risks and graphql-go gaps

G1. **Directives on input fields are refused.** velox's rule "a directive
that guards a field guards its filters and writes" depends on gqlgen running
INPUT_FIELD_DEFINITION directives. graphql-go fails NewSchema instead.
Interim: in graphql-go mode the SDL leaves application directives off input
fields; the plugin emits a table (input type, field → directive names) and
`graphqlgo.Directive(name, fn)` binds `fn` to output fields with
`graphql.Directive` and runs the same `fn` for each given guarded input field
from the OperationInterceptor's argument walk. Introspection then does not
show the input-field directives.

G2. **No public identity for a field occurrence.** Batch keys and the
Selected cache use the `Selection` value, which is comparable only because
it is a struct of one unexported pointer. That is undocumented and shared
across fragments, so two aliases can share a key.

G3. **Concurrency model.** Resolve fields are concurrent by default, a
transaction's DB is not safe for concurrent use, and the wave coordinator
counts any blocked goroutine as running. Section 2.5 handles velox's fields;
an application field under a mutation needs the opt-in interceptor.

G4. **Untagged, experimental surface.** graphql-go has no tag;
`WaveCoordinator` and `QueryCost` are Experimental; gqlparser v2's AST is in
its API. velox depends on the binding constructors, interceptors,
`FieldFrom`/`Selection`/`ArgumentMap`, `ExtensionsProvider`, `Waves()` and
the transports. Mitigation: one adapter module pinned to a pseudo-version,
the parity suite to catch drift, velox 1.0 after a graphql-go tag.

G5. **Semantics that move.** MaxResponseBytes counts all of `data`, not
strings. An enum value outside the SDL is an error, not written raw.
Explicit-null detection reads ArgumentMap, a second decode of the
arguments. Each is documented and tested.

G6. **Compile cost is lower, but not by much yet.** Measured in section 4:
about 40% less CPU and 25% less peak than gqlgen at N=100. graphql-go's own
docs/performance.md calls compile time "a wash". Each struct type bound by
`Object`, `Input` or `Args` is its own generic shape, and the constructors'
closures are inlined into every call site. velox's own wrappers recover
little (section 4); A7 can. Phase 4 also tries the bindings in a `gen/graphqlgo` subpackage, which
splits the peak between two compile processes at about the same CPU.

G7. **No schema in OperationContext.** Cost and the null walk need it, so
`With` takes it.

### Asks of graphql-go (the user's repository: asks, not velox work)

- A1. Run a bound directive at INPUT_FIELD_DEFINITION when a request gives
  that field, as gqlgen does, instead of refusing it (closes G1).
- A2. A stable, documented, comparable identity per field occurrence, e.g.
