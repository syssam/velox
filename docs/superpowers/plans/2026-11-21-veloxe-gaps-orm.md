# veloxe gaps, phase A: ORM runtime — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give velox2 the veloxe/ent runtime features nextapp and typical ent apps rely on that velox2 lacks, in velox2's own design (no per-entity builders, behaviour fails closed, ent names where they fit).

**Architecture:** Generic root functions/methods and DB options over the existing engine; no change to generated code's shape unless a task says so. One ADR per new behavioural surface.

**Tech Stack:** Go 1.27, velox root + `internal/engine`, `privacy`, `schema/mixin/softdelete`; PostgreSQL 18/16, MySQL 8.4, SQLite.

**Spec:** `docs/superpowers/specs/2026-11-21-veloxe-gap-analysis.md` §2.1 items 3–9, 11–13 and §2.2 (Distinct, Explain, UpdateAll, privacy combinators/trace). The Decisions below settle every choice that section left open; the user's instruction was "follow your idea, and more".

## Decisions (binding)

D1. **Hooks for every entity.** `velox.WithHooksAll(hs ...Hook) Option` (the existing `Hook`, hook.go:65). They run for every entity's mutation, outside (before) the entity's own `WithHooks[E]` and schema hooks, in registration order. The entity is named by the Mutation (add `Mutation.Entity() string` if absent, the schema name). Same transaction, error and recording rules as `WithHooks[E]`.

D2. **Row filters for every entity.** `velox.WithFilter(f Filter) Option` with `type Filter func(ctx context.Context, entity string) (Predicate, error)` (a `Predicate` built by name: `velox.FieldEQ`… as schema Interceptors use). Reach: identical to a schema Interceptor — every read, write, load, join, `Has`/`HasWith` subquery, count, aggregate, paginate. `WithoutPolicy` does not lift it. A returned error fails the statement; a zero `Predicate` fails the statement; a nil-valued "no filter" is `velox.NoFilter` (an explicit sentinel `Predicate`, so forgetting to return one fails closed). Several filters AND together. Columns named by a filter are checked at run time (an unknown column fails the statement). ADR required.

D3. **KeepDefaults.** First establish (test) whether an explicit `Set` on an `UpdateDefault` column already wins. Then add `UpdateQuery.KeepDefaults(cols ...Column[E])` and the same on `SaveQuery` (and untyped equivalents if untyped has update builders): the named columns' `UpdateDefault` does not fire. A column without an `UpdateDefault` → error at execution (fail closed, message names it).

D4. **SetPtr.** `SetPtr(p *V) Setter[E]` on every handle kind that has `Set`, generated by `internal/handlegen` (lazy generic like the others; compile-cost bounds must not rise). A nil `p` yields a setter the builders skip (no column written); non-nil sets `*p`. On Null kinds a nil `p` also skips (ent's `SetNillableX` semantics); `SetNull()` stays the way to write NULL. Works in Insert (skipped column = not set, lean-insert rules apply), Update, Save, upsert.

D5. **Error helpers.** `velox.IsConstraintError(err) bool` (unique/FK/check/not-null violation from the driver — reuse `internal/dberr`), `velox.IsValidationError(err) bool`, `velox.IsNotSingular(err) bool` (a `One`/`Only` that found more than one row — check the existing error name). Typed-nil safe, `errors.As` based. **No** `OpCreate`/`OpUpdateOne`/`OpDeleteOne` aliases: velox keeps one name per op; Phase D's migration guide maps them.

D6. **AfterCommit.** `velox.AfterCommit(ctx context.Context, fn func(context.Context)) error`. Inside a `db.Tx` (or `UseTx`) frame: queue fn on the transaction; run all queued fns in order after the outermost COMMIT succeeds, with a context detached from cancellation (`context.WithoutCancel`). Never on rollback. A savepoint rolled back drops the fns queued inside it. Outside a transaction it returns an error (fail closed). A panicking fn does not stop the others; the first panic re-panics after all ran (document).

D7. **Values / IDs.** `velox.Values[E any, V any](ctx, q Query[E], col Column[E] /* typed value handle */) ([]V, error)` — pick the exact parameter type so `velox.Values(ctx, q, I.Number)` infers `V`; and `velox.IDs[E](ctx, q) ([]int64 or key type, error)` using the key. Read policy, scope and filters apply; same Limit/AllowUnbounded rule as reads. Functions, not methods (ADR 0022).

D8. **WithLog.** `velox.WithLog(l *slog.Logger, opts ...LogOption) Option`, `velox.LogArgs()` option. Logs each statement at Debug: SQL, duration, rows affected/returned, error. Arguments only with `LogArgs()`, and a `Sensitive` column's argument is always replaced by `"<sensitive>"`. Implemented on the existing Around mechanism; zero cost when not set.

D9. **Window functions in projections.** `Calc`/`SelectRaw` text may contain `OVER (...)` window clauses; subqueries stay refused. Test `COUNT(*) OVER ()` with GroupBy pagination on the three dialects (SQLite ≥3.25 supports windows).

D10. **Soft-delete options.** `softdelete.Mixin{Assign: func(ctx) []velox.Assignment...}` (exact type: whatever lets a `deleted_by` column be set from ctx at delete time) and `Reads: softdelete.Unfiltered` (soft-deleted rows visible to reads by default; deletes still soft). Defaults unchanged.

D11. **Back-references.** Grep nextapp-graphql's non-generated code for reads of a child's back edge after loading it through the parent (`.Edges.Parent` style after `WithChildren`). If none: drop the item and record it in the ADR index notes. If some: `Rel.WithBack()` load option filling the inverse `One`, JSON skipping back-refs.

D12. **Small ent parity (§2.2).**
- `Query.Distinct()` for projections (Select/Calc) only; on an entity read it errors.
- `Query.Explain(ctx) (string, error)` running the dialect's EXPLAIN on the query's SQL with policies applied.
- `InsertQuery.UpdateAll()` on upsert: every column except the key and the conflict columns, ADR 0017's UpdateDefault rule kept.
- `privacy.And`, `privacy.Or`, `privacy.Not` over rules, and `privacy.WithTrace(ctx, func(Decision))` reporting each rule's decision (veloxe names).

## Global Constraints

- No change to generated code's shape except D4 (handles.go only, root) — no `GeneratedCodeIsVersion` bump unless generated packages change.
- `TestGenericTypesCompileSmall` bounds are not raised.
- Public API through the snapshot, diff read. Every exported identifier documented.
- Every behaviour has a test that failed before it; PG/MySQL-specific behaviour gets an integration test (`internal/integration`, skips locally, runs in the gate).
- Nothing about filters or hooks is stored in a context except what already is.
- Commit style `area: what`, staged by name, ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Subagents never run `scripts/ci-local.sh` or docker. Never push.
- Each new behavioural surface gets an ADR (numbers from 0098 (0097 is taken by the generate package on a parallel branch)) and a README row; CHANGELOG "Added".

## Review Focus

1. A WithFilter that returns an error or zero Predicate on a `HasWith` subquery / eager load / join: statement fails, no rows leak.
2. WithFilter + WithoutPolicy: the filter still applies.
3. AfterCommit inside a savepoint that rolls back, then outer commit: the inner fn does not run.
4. SetPtr(nil) on an Insert of a column with a declared DB default: the default applies (lean insert), validation skipped as ADR 0093's rule.
5. WithLog never prints a Sensitive argument, even with LogArgs.
